# AI学習ポータル 仕様書

部署メンバーが、データ分析・統計の基礎から実践レベルまでを、概念の説明とハンズオン(ブラウザ内で Python を実行する
Colab 風のセル)で学ぶための部署内学習サービス。

## 決定事項

| 項目 | 決定内容 |
|---|---|
| 単元画面 | ワイヤーフレーム案A(ノートブック型:説明・例題・演習のセルを縦に並べる) |
| フロントエンド | React + TypeScript(Vite)の SPA |
| バックエンド | Python / FastAPI、SQLAlchemy 2、Alembic |
| DB | MySQL 8(ローカル)。Azure では Azure Database for MySQL を想定 |
| 配置 | Azure(App Service または Container Apps)。IP 制限はプラットフォーム側で設定 |
| 認証 | ログイン名 + パスワード。管理者 / ユーザの2区分 |
| コード実行 | ブラウザ内(Pyodide 314、モジュール Worker)。サーバでは受講者のコードを実行しない |
| 採点 | 出力一致 / テストコード / 選択式(小テスト)。正解データはサーバ側だけに持つ |
| 単元の完了 | 単元内の演習をすべて正解したとき(全単元に演習が1問以上必要) |
| 小テスト | 各講座 10 問程度。単元の内容に合わせて選択式・数値入力・コードから最適な形式を選ぶ。講座の全単元を完了した後に受験できる |
| 講座の修了 | 小テストで満点。再受験は自由。修了後に演習が変更されても修了のまま |
| 公開 | 管理者は承認なしで公開できる。公開後に演習を変えた場合はその演習だけ再検証 |
| 検証の一致判定 | 作成者の解答の出力と、AI の想定出力(Pyodide で実行)が一致するか |
| 受講状況の閲覧 | ユーザは自分の分のみ、管理者は全員分。人事評価には使わない |

## 開発フェーズ

| フェーズ | 範囲 | 状態 |
|---|---|---|
| 1. 受講の土台 | ログイン、講座一覧、講座詳細、単元画面(案A)、Pyodide 実行、演習の採点、進捗記録、.ipynb 取り込み(CLI) | **実装済み** |
| 2. 修了まで | 小テスト、修了判定、マイページ、ホーム、講座カタログ | **実装済み** |
| 3. 管理者機能 | 講座管理、講座の作成(白紙から)、単元エディタ、小テストの編集、作成者による検証、データファイル、公開前チェック、メンバーの受講状況、メンバー管理 | **実装済み** |
| 4. 作成の効率化 | 画面からの .ipynb 取り込み、AI による構成案・下書き生成、DB の自動起動・停止、Azure のデプロイ手順 | **実装済み**(デプロイは未実施) |

## 構成

```
ブラウザ ── React SPA ──┬─ CodeMirror 6(セル編集)
                       ├─ react-markdown + KaTeX(説明・数式)
                       └─ Web Worker ─ Pyodide(pandas / numpy / matplotlib / scikit-learn / statsmodels)
            │ REST(JSON)+ 署名付きセッション Cookie
FastAPI ──┬─ 認証・権限
          ├─ 講座・単元・問題の提供(想定出力・解答は返さない)
          ├─ 採点・進捗記録
          └─ .ipynb 取り込み(nbformat)
            │ SQLAlchemy 2 / Alembic
MySQL 8
```

本番ではフロントエンドのビルド成果物をバックエンドが同じオリジンで配信する(CORS 不要)。

### ブラウザ内実行の仕組み

- Pyodide は Web Worker で動かす(画面が固まらない。無限ループは Worker ごと停止する。上限 120 秒)。
- 単元ごとに Python の名前空間を分け、同じ単元のセルは変数を共有する(Colab と同じ)。
- 最後の行が式ならその値を表示する(Jupyter と同じ)。この表示も採点対象の出力に含む。
- matplotlib の図は Agg で描画し、PNG にして表示する。
- 講座のデータファイルは実行前に Worker の作業ディレクトリへ配置する。
- 配信元は `PYODIDE_BASE_URL` で切り替える(既定は jsDelivr CDN)。

### 採点の流れ(コード問題)

1. ブラウザで受講者のコードを実行する(テストコード採点なら続けてテストを実行)。
2. 出力・エラー・テスト結果を `POST /api/problems/{id}/submit-code` に送る。
3. サーバが想定出力と比較(`app/services/grading.py`)し、提出を記録する。
4. 単元内の演習がすべて正解になったら `unit_progress` に完了を記録する。

テストコード採点の問題は、テストコードをブラウザに渡すため開発者ツールで見えてしまう(部署内の学習用途のため許容)。

### 小テスト

- 講座の全単元を完了したユーザだけが受験できる(サーバ側でも確認し、未完了なら問題を返さない)。
- 選択式・数値入力はサーバで採点する(数値は全角・カンマ区切りも受け付け、許容誤差内なら正解)。
  コード問題は演習と同じく、ブラウザで実行した出力をサーバで想定出力と比べる。
- 採点のたびに受験記録(`quiz_attempts`)を作る。満点なら `course_completions` に修了を記録する。
- 正解した問題には解説を、不正解の問題には関連単元へのリンクを返す。

### 作成者による検証(管理者)

- コード問題(演習・小テスト)は、作成者の解答をブラウザで実行して検証する。
  - AI の模範解答がある場合:その出力と作成者の出力が一致すれば「検証済み」(AI の出力が想定出力)、一致しなければ「不一致」。
    不一致は「AI の模範解答を表示」で確認し、必要なら「自分の解答を正とする」で検証済みにする。
  - AI の模範解答が無い場合:作成者の出力を想定出力として「検証済み」。
  - テストコード採点の問題は、作成者の解答(と AI の模範解答)がテストに合格すること。
- 選択式・数値入力は、正解が正しく設定されていれば保存時に検証済みになる。
- 採点に関わる項目(問題文・初期コード・採点方式・テストコード・選択肢・正解・許容誤差・解答)を変えた問題は、
  内容バージョンを上げて未検証に戻す(その問題だけ再検証)。ヒント・解説・タイトルの変更は再検証不要。
- 公開の条件:講座情報が入力済み・全単元に演習あり・全問題が検証済み・小テストあり・例題コードがブラウザでエラーなく実行できる。

### AI による講座作成

プロンプトや構成は今後調整していく前提のため、**入力・出力の型と、アプリとの接続部分を固定**し、プロンプトはシンプルにしている。

```
画面(題材)─→ POST /api/admin/ai/outline ─→ 構成案(CourseOutline)─→ 画面で編集
画面(構成案)─→ POST /api/admin/ai/drafts ─→ 講座(下書き)+ 単元 + ジョブを登録
                                         └─ バックグラウンド:単元ごとに UnitDraft、最後に QuizDraft を生成して保存
画面 ─→ GET /api/admin/ai/jobs/{id}(3 秒ごと)─→ 進捗表示 → 完了後に講座エディタで検証
```

| 部分 | ファイル | 内容 |
|---|---|---|
| 接続 | `app/ai/client.py` | Azure OpenAI(OpenAI SDK + `base_url`、JSON 応答)。`AIClient` 型に依存するため差し替え可能 |
| 入出力の型 | `app/ai/schemas.py` | 依頼(`OutlineRequest`)と応答(`CourseOutline` / `UnitDraft` / `QuizDraft`)。応答はこの型で検証する(null は既定値として扱う) |
| プロンプト | `app/ai/prompts.py` | 版番号 `PROMPT_VERSION` 付き。受講環境(Pyodide・使えるライブラリ・データの作り方)と出力の JSON スキーマを渡す |
| 呼び出しの流れ | `app/ai/generator.py` | 呼び出し → 型で検証 → 形式が崩れていたら誤りを添えて 1 回だけ再試行 → すべて `ai_generations` に記録 |
| 保存 | `app/services/ai_course_service.py` | 下書きを DB に保存。演習・小テストは**すべて未検証**、AI の模範解答は `ai_model_answer`、作成者の解答は空 |

- ジョブは単元ごとに進捗を記録する。一部の単元で失敗しても続け、失敗した内容を残す。
- アプリの停止などで止まったジョブは、次の起動時に「中断」になる。「続きから再開」で中身の無い単元と小テストだけを作る。
- 選択式・数値入力は、作成者が内容を確認して「確認済み」にする(`POST /problems/{id}/confirm`)。

### DB の自動起動・停止(Azure)

- Azure Database for MySQL(フレキシブルサーバー)には接続時の自動起動が無いため、アプリが Azure の管理 API で起動する。
- DB に接続できない例外が出たら、DB が停止中なら起動を要求して `503 {code: "db_starting"}` を返す。画面は起動待ちの表示にし、
  15 秒ごとに `/api/health` を確認してつながったら再読み込みする。
- API へのアクセスごとに最終アクセス日時を `app_state` に記録する(1 分に 1 回まで)。
  スケジュールジョブが `python -m app.cli db-idle-stop` を 15 分ごとに実行し、60 分使われていなければ DB を停止する。
- ローカルでは `DB_AUTOSTART_ENABLED=false`(接続できなければ「データベースに接続できません」)。

## データモデル

| テーブル | 内容 |
|---|---|
| `users` | ログイン名・表示名・パスワードハッシュ(scrypt)・管理者フラグ |
| `courses` | 講座(識別名・タイトル・概要・レベル・タグ・身につくこと・使用ライブラリ・公開状態・作成者) |
| `course_prerequisites` | 前提講座 |
| `units` | 単元(並び順・タイトル・概要・学習目標・目安時間) |
| `cells` | 単元のセル(説明 / 例題コード / 演習)。演習セルは `problems` を参照 |
| `problems` | 演習と小テストの問題(同じ構造)。問題文・初期コード・採点方式・想定出力・テストコード・選択肢・正解・解説・AI の模範解答・作成者の解答・検証状態・内容バージョン |
| `datasets` | 講座のデータファイル(DB に格納) |
| `unit_progress` | 単元の完了記録 |
| `submissions` | 提出記録(回答・出力・正誤・問題の内容バージョン。小テストの回答は受験記録 ID を持つ) |
| `quiz_attempts` | 小テストの受験記録(得点・問題数) |
| `course_completions` | 講座の修了記録 |
| `ai_jobs` | AI による下書き生成のジョブ(状態・進捗・失敗内容・生成時の依頼と構成案) |
| `ai_generations` | AI 呼び出しの記録(用途・モデル・プロンプトの版・プロンプト・応答・成否・所要時間) |
| `app_state` | アプリの状態(最終アクセス日時。DB の自動停止の判断に使う) |

テーブル定義は `backend/app/models.py`。変更したら Alembic でマイグレーションを作る。
