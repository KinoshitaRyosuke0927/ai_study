# 予測モデル設計書

## 概要

ウォーターサーバーの翌月の注文量を、Ridge回帰（L2正則化線形回帰）を用いて予測する。  
モデルの学習・推論はAPIリクエストのたびにオンザフライで実行される（モデルのファイル保存は行わない）。

---

## モデル概要

| 項目 | 内容 |
|------|------|
| モデル種別 | Ridge回帰（L2正則化線形回帰） |
| ライブラリ | scikit-learn `sklearn.linear_model.Ridge` |
| 正則化強度 alpha | LOO-CVにより候補 `[0.01, 0.1, 1.0, 10.0, 50.0, 100.0]` から最小MAEを選択 |
| 評価指標 | MAE（平均絶対誤差） |
| 交差検証 | LOO-CV（Leave-One-Out Cross Validation）※サンプル数が少ないため |
| 実装ファイル | `app.py`（`_run_prediction()`関数）、`water_demand_model.py`（実験用スクリプト） |

## インプットデータ

### 学習データソース

| データ名 | ファイル | 概要 |
|----------|----------|------|
| 水の注文量実績 | `train_data/water_demand.csv` | 月ごとの注文量（目的変数）|
| JBD営業日カレンダー | `train_data/jbd_calendar.csv` | 日ごとの営業日フラグ |
| AIC出社カレンダー | `train_data/work_day.csv` | 社員ごとの日次出社フラグ |
| 気象データ | `train_data/weather_data.csv` | 日次の平均気温・最低気温・最高気温 |

### 各CSVのスキーマ

#### water_demand.csv（目的変数）

| 列名 | 型 | 概要 |
|------|----|------|
| `date_ym` | 日付（YYYY/MM/DD形式、DDは常に01） | 対象年月 |
| `order_quantity` | float | 注文量（L）← **目的変数** |
| `remaining_quantity` | float（欠損あり） | 残量（L）※現時点では予測に未使用 |

#### jbd_calendar.csv

| 列名 | 型 | 概要 |
|------|----|------|
| `date` | 日付（YYYY/M/D形式） | 年月日 |
| `business_day_flag` | int（0 or 1） | 営業日=1, 休業日=0 |

#### work_day.csv

| 列名 | 型 | 概要 |
|------|----|------|
| `date` | 日付（YYYY/M/D形式） | 年月日 |
| `emp_01` 〜 `emp_12` | int（0 or 1） | AICに出社=1, 不在=0（社員ごとに列が存在） |

#### weather_data.csv

| 列名 | 型 | 概要 |
|------|----|------|
| `date` | 日付（YYYY-MM-DD形式） | 年月日 |
| `tavg` | float | 平均気温（℃） ← **予測に使用** |
| `tmin` | float | 最低気温（℃） |
| `tmax` | float | 最高気温（℃） |

### 特徴量エンジニアリング

月次データに変換するため、以下の集計処理を実施する。

| 特徴量名 | 集計元 | 計算方法 |
|----------|--------|----------|
| `business_days` | jbd_calendar.csv | 月ごとに `business_day_flag` を合計（月次営業日数） |
| `total_attendance` | work_day.csv × jbd_calendar.csv | 社員全員の日次出社フラグを合算し、営業日フラグを掛けた後に月次合計（月次延べ出社人数） |
| `attendance_rate` | 上記2つから計算 | `total_attendance ÷ business_days`（月次平均出社人数）|
| `tavg_mean` | weather_data.csv | 月ごとに `tavg` を平均（月次平均気温）|

> **注意：** 出社人数の集計では、JBDカレンダーに存在しない日付は休業日として扱われる（`fillna(0)`）。

### モデルへの入力特徴量（最終）

| 特徴量 | 単位 | 説明 |
|--------|------|------|
| `business_days` | 日 | 予測対象月の営業日数 |
| `attendance_rate` | 人/日 | 予測対象月の1日あたり平均出社人数 |
| `tavg_mean` | ℃ | 予測対象月の月平均気温 ※前年同月実績で代替 |

## アウトプットデータ

### 予測値

| 項目 | 説明 |
|------|------|
| `prediction` | モデルの生の予測注文量（L）、小数第1位に丸め |
| `prediction_rounded` | 20L単位に切り上げた推奨注文量（L）、`ceil(prediction / 20) * 20` |

### APIレスポンス全体（`POST /predict/run`）

| フィールド | 型 | 内容 |
|------------|----|------|
| `target_month` | string | 予測対象月（例：「2025年11月」） |
| `date_ym_csv` | string | CSV保存用の日付文字列（例：「2025/11/01」） |
| `business_days` | int | 予測対象月の営業日数 |
| `attendance_rate` | float | 1日あたり平均出社人数 |
| `tavg_prev_year` | float | 使用した気温（前年同月実績）|
| `prediction` | float | 生の予測注文量（L）|
| `prediction_rounded` | int | 推奨注文量（20L単位、L）|

エラー時：

| フィールド | 型 | 内容 |
|------------|----|------|
| `error` | string | エラーメッセージ |

## 予測の実行フロー

```
1. CSVデータ読み込み（4ファイル）
        ↓
2. 前処理（日付型変換・年月Period列作成）
        ↓
3. 月次特徴量の集計
   - 月次営業日数（business_days）
   - 月次延べ出社人数 → 平均出社人数（attendance_rate）
   - 月次平均気温（tavg_mean）
        ↓
4. 学習データ構築（欠損行を除外）
        ↓
5. LOO-CVによるalphaの選択（候補：0.01, 0.1, 1.0, 10.0, 50.0, 100.0）
        ↓
6. 最良alphaでRidge回帰モデルを学習
        ↓
7. 予測対象月の特徴量を準備
   - business_days ← jbd_calendar.csvの翌月データ
   - attendance_rate ← work_day.csvの翌月データ
   - tavg_mean ← weather_data.csvの前年同月実績（※翌月の実測値が存在しないため）
        ↓
8. 予測実行 → prediction（L）
        ↓
9. 20L単位に切り上げ → prediction_rounded（L）
        ↓
10. 結果を返却
```

## エラー条件

| 条件 | エラーメッセージ |
|------|-----------------|
| 予測対象月の営業日カレンダーデータが不足 | 「予測月 {月} のカレンダーデータが不足しています」 |
| 予測対象月の出社データが不足 | 「予測月 {月} のカレンダーデータが不足しています」 |
| 前年同月の気温データが存在しない | 「前年同月（{月}）の気温データがありません」 |

## 予測精度の課題と今後の改善方向

| 課題 | 説明 | 改善案 |
|------|------|--------|
| 翌月の気温が不明 | 前年同月の実績値で代替しているため、年ごとの気候変動を反映できない | 気象庁・天気予報APIから翌月の予測気温を取得 |
| 翌月の出勤状況が不明 | 予測時点で確定していない場合がある | 入力精度の向上（早期のカレンダー確定）|
| 湿度データが未取得 | 水消費量への影響が見込まれるが現APIでは取得不可 | 湿度取得可能なAPIへの切り替え |
| サンプル数が少ない | LOO-CVを採用しているが、データ蓄積で精度が向上する見込み | 実績データの継続的な蓄積 |
