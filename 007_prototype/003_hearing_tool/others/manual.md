# ヒアリング管理ツール 使い方

ヒアリングの準備、当日の進行、事後の整理、分析を1か所で行うツールです。
自分のPCだけで動きます。インターネットに送るのは、文字起こしをするときの音声だけです。

---

## 1. はじめに（初回だけ）

1. ZIPを好きな場所に展開します（例：`C:\tools\hearing_tool\`）。
   OneDriveなど、同期されるフォルダは避けてください。
2. `起動.bat`（または `hearing_tool.exe`）をダブルクリックします。
   - 黒いウィンドウが開き、少し待つとブラウザで画面が開きます。
   - 開かないときは、ブラウザで http://localhost:8000 を開きます。
   - 「WindowsによってPCが保護されました」と出たら、「詳細情報」→「実行」を押します。
3. 左のメニューの「入出力と設定」で、**更新者の名前**を自分の名前にして「保存」を押します。
   この名前は、追加・編集したデータに記録されます。
4. ほかの人からデータのZIPを受け取っている場合は、「入出力と設定」で取り込みます（→ 6章）。

初回の起動で、同じフォルダに `config.json`（設定）と `data\`（データ）が作られます。

### 終了するとき

**黒いウィンドウを閉じます。** ブラウザを閉じただけでは終了しません。
データは操作するたびに保存されているので、終了の前に保存する必要はありません。

---

## 2. 画面の構成

| メニュー | できること |
|---|---|
| ホーム | 対象者と回の一覧、次にやること |
| 課題カード | 見つかった課題の一覧と編集 |
| データ台帳 | 課題に関係するデータの一覧と、確認の状態 |
| 横断表示 | 複数の人に共通する課題、確認していないデータ |
| 評価表と解決策 | 課題の評価、解決策の候補、提案用の整理の出力 |
| 共通の質問 | どの回でも使う質問のひな形 |
| 用語集 | 用語と、誤認識されやすい表記 |
| 入出力と設定 | 資料の出力、データの受け渡し、更新者の名前 |

文章の欄は、Markdownで書けます。編集画面の「記述」と「プレビュー」で表示を切り替えられます。

---

## 3. ヒアリングの準備

1. 「ホーム」で対象者を選びます（新しい人は「対象者を追加」）。
2. 対象者の画面で「回を追加」し、回を開きます。
3. 回の画面で、次のものを用意します。
   - **基本情報：** 日時、目的など（「基本情報を編集」）
   - **課題の仮説：** その人の課題として考えていること
   - **タイムテーブル：** 「区切りを追加」で時間の区切りを作り、区切りごとに「質問を追加」
     - 「共通の質問から追加」で、ひな形の質問を入れられます。
     - 重要度が◎の質問の時間が区切りの長さを超えると、警告が出ます。
     - 前回聞けなかった◎の質問は、追加の候補として表示されます。
   - **当日画面に出す要約**と**事前の依頼文**
4. 「入出力と設定」の「進行資料を出力」で、進行資料をMarkdownにできます。

### 公開範囲

要約や課題などには、公開範囲を付けます。

| 公開範囲 | 使われる場所 |
|---|---|
| 本人に見せる | 本人向けの表示、本人向けの要約、事前の依頼文 |
| 聞き手のみ | ツールの中だけ（既定） |
| 提案に使う | 提案用の整理 |

**本人向けの表示や出力に、聞き手のメモが混ざらないよう、公開範囲を確認してください。**

---

## 4. ヒアリングの当日

回の画面の「当日の進行」を開きます。

1. 「開始」を押すと、区切りごとのタイマーが動きます。
2. 質問ごとに「聞いた」「省略」を押し、メモを書きます。メモは、入力欄の外を押すと保存されます。
3. 終わったら「実施済みにする」を押します。

本人に画面を見せるときは、「本人向けの表示を開く」を押します。
公開範囲が「本人に見せる」の要約だけを、別のウィンドウに大きく表示します。

---

## 5. ヒアリングの後

### 文字起こし（AzureのAIを使う）

文字起こしを使うには、Azure上のAIの接続情報を記載した `.env` を `hearing_tool.exe` と同じフォルダに置きます。
**`.env` にはAPIキーが入っているので、ほかの人に渡したり、共有フォルダに置いたりしないでください。**

1. 録音のファイルを `data\audio\` に置きます。
2. 回の画面で「文字起こしと推敲」を開き、音声ファイルを選びます。
3. 音声の長さ、AIを呼び出す回数、料金と時間の目安が表示されるので、確認します。
4. 「文字起こしを実行」を押します。1時間の録音で10分ほどかかります。
   途中で止まっても、もう一度押せば続きから再開します。

### 推敲

文字起こしの結果は、1文ずつの発言になります（発言者は空欄）。

1. 「▶ 時刻」のボタンで、その位置から音声を再生しながら、文ごとに発言者を選びます。
2. 「続けて同じ発言者の発言をまとめる」で、発言者ごとにまとめます。
3. 「「イサイ」→「砂盃」」のような候補のボタンで、誤認識を直します。
   候補は、用語集の「誤認識されやすい表記」から作られます。
4. 雑談などは「対象外」にし、確認した発言を「推敲済み」にします。
5. 必要に応じて「ひも付け」で、発言を質問や課題に結び付けます。

「↑結合」「分割」「＋下に追加」で、発言の区切りも直せます。

## 6. 整理と分析

| 画面 | やること |
|---|---|
| 課題カード | 見つかった課題を書き、テーマと公開範囲を付ける |
| データ台帳 | 課題に関係するデータを書き、本人に確認したかを記録する |
| 横断表示 | 複数の人に共通する課題や、確認していないデータを見る |
| 評価表と解決策 | 課題×観点の表のセルを押して、◎○△×と理由を入れる。解決策の候補を書く |

「評価表と解決策」の「提案用の整理を出力」で、公開範囲が「提案に使う」の課題をMarkdownにできます。
対象者の名前を「メンバー1」などに伏せて出力することもできます。

---

## 7. ほかの聞き手とデータを受け渡す

データはツールごとに別々です。自動では同期されないので、ZIPで受け渡します。

### 渡すとき

1. 「入出力と設定」の「ZIP を書き出す」を押します。
2. できたZIPを相手に渡します（`data\exports\` にも残ります）。
3. 音声はZIPに入らないので、必要ならファイルを直接渡します。

**ZIPには発言や個人の情報が入っています。** ヒアリングの対象者本人を含め、聞き手以外には渡さないでください。

### 受け取るとき

1. 「入出力と設定」でZIPを選び、「内容を確認」を押します。
2. 追加・上書きされる件数を確認し、「取り込む」を押します。
   - 同じデータは、更新日時が新しいほうが残ります。
   - 取り込む前の状態は、自動で `data\backups\` に保存されます。
   - 相手が削除したデータは、こちらでは削除されません。
3. 音声を受け取ったら、`data\audio\` に置きます。

## 8. 困ったとき

| 状況 | 対処 |
|---|---|
| 画面が開かない | 黒いウィンドウが開いているか確認し、ブラウザで http://localhost:8000 を開く |
| 「ポート 8000 はすでに使われています」と出る | すでに起動しています。ブラウザで http://localhost:8000 を開く |
| 保存できないと表示される | `data\` のCSVをExcelで開いていたら閉じる |
| 文字起こしが実行できない | `.env` がexeと同じフォルダにあるか、音声ファイルを選んだか確認する |
| ウイルス対策ソフトに止められた | 社内の担当者に相談する |
| データを前の状態に戻したい | ツールを終了し、`data\backups\` の中のフォルダ（名前は日時）から必要なCSVを `data\` にコピーする |

### 新しい版を受け取ったとき

`hearing_tool.exe` と `_internal\` だけを置き換えます。`config.json`、`.env`、`data\` はそのまま使えます。
念のため、置き換える前に `data\` をコピーしておいてください。

### 消してはいけないもの

| ファイル・フォルダ | 中身 |
|---|---|
| `_internal\` | ツールの部品 |
| `data\` | すべてのデータ（CSV、音声、出力、バックアップ） |
| `config.json` | 更新者の名前などの設定 |
