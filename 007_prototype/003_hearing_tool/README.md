# ヒアリング管理ツール 仕様

ヒアリングの準備、当日の進行、事後の整理、分析を1か所で行うためのローカルツールです。
聞き手が自分のPCで1人ずつ使います。AzureのAIは文字起こしにだけ使います。

---

## 1. 前提

| 項目 | 内容 |
|---|---|
| 利用者 | ヒアリングの聞き手。1人ずつ、自分のPCで使う |
| 動作環境 | ローカル。Azureを使うのは文字起こしだけ |
| データ | CSVファイル。データベースは使わない |
| 共有 | CSVをZIPで書き出して渡す。受け取った人は取り込んで、そのまま追記する。音声や動画はZIPに含めず、ファイルを直接渡して `data/audio/` に置く |
| 統合と比較 | ツールでは行わない。利用者が行う |
| 構成 | バックエンドはPython（FastAPI）、画面はHTMLとJavaScript（ビルド不要） |
| ポート | 8000 |

### 起動方法

`003_hearing_tool` フォルダで次を実行し、ブラウザで http://localhost:8000 を開きます。

```powershell
# 初回だけ：仮想環境を作り、パッケージを入れる
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt

# 初回だけ：設定ファイルを作り、user_name を自分の名前にする
Copy-Item config.example.json config.json

# 初回だけ：既存の資料を取り込む（やり直すときも同じ）
.\.venv\Scripts\python.exe -m tools.import_existing

# 起動（ブラウザも自動で開く）
.\.venv\Scripts\python.exe run_app.py
```

`.\.venv\Scripts\python.exe -m uvicorn app.main:app --port 8000` でも起動できます（ブラウザは開きません）。

## 3. CSVの共通ルール

| 項目 | ルール |
|---|---|
| 文字コード | BOM付きUTF-8（Excelで開いても文字化けしない） |
| 改行を含む文章 | 引用符で囲んで保存する（Pythonのcsvモジュールに任せる） |
| ID | UUIDの先頭12文字など、重複しない文字列。連番は使わない |
| 共通の列 | すべてのCSVに `updated_by`、`updated_at` を持たせる |
| 複数の参照 | 1つの列に複数のIDを入れるときは `;` で区切る |
| 公開範囲（`visibility`） | `本人に見せる`、`聞き手のみ`、`提案に使う` のいずれか。未指定は `聞き手のみ` |
| 書き込み | 一時ファイルに書いてから置き換える（書き込み途中で壊れないように） |

### 別の人のデータを取り込むとき

- 同じIDの行は、`updated_at` が新しいほうを残します。
- 上書きされる行があるときは、取り込む前に件数を表示して確認します。
- 取り込む前に、今の `data/` を `backups/` に自動で保存します。
- ZIPに入るのはCSVだけです。音声や動画は、ファイルを直接受け取って `data/audio/` に置きます。
  取り込むデータが参照している音声が置かれていなければ、確認の画面にファイル名を表示します。
- 行の削除は、取り込みでは反映されません。

## 5. 画面

| 画面 | 内容 |
|---|---|
| ホーム | 対象者と回の一覧、状態、次にやること（準備の警告、聞けなかった◎の質問、推敲していない文字起こしなど） |
| 対象者 | 回の一覧、仮説、課題カード、データ台帳 |
| 回の準備 | 目的、タイムテーブル、質問の編集、共通の質問の追加、要約、依頼文 |
| 当日の進行 | 区切りごとのタイマー、質問ごとのメモ、聞いたかどうかのチェック |
| 本人向けの表示 | 公開範囲が `本人に見せる` の要約だけを、別のウィンドウに大きく表示する |
| 文字起こしと推敲 | 文字起こしの実行、音声の再生、発言の編集、発言者の付け替え、誤認識の候補の表示、ひも付け |
| 課題カード | 一覧と編集、仮説とのひも付け |
| データ台帳 | 一覧と編集、確認の状態での絞り込み |
| 横断表示 | 複数の人に共通する課題、確認していないデータ |
| 評価表と解決策 | 課題ごとの評価、解決策の候補、評価の観点、提案用の整理の出力 |
| 共通の質問 | どの回にも追加できる質問のひな形 |
| 用語集 | 一覧と編集。誤認識されやすい表記は、推敲画面の置き換えの候補になる |
| 入出力と設定 | Markdownの出力、ZIPの書き出しと取り込み、更新者の名前 |

文章の欄はMarkdownで書けます。編集では「記述」と「プレビュー」を切り替えられます。

### 準備画面での集計と警告

- 区切りごとに、◎と○の質問の数と、目安の時間の合計を表示します。
- ◎の質問の時間が区切りの長さを超えたら警告します。
- 合計が予定の時間を超えたら警告します。
- 前回の回で `聞いた` になっていない◎の質問と、`未確認` の仮説を、追加の候補として表示します。

### Markdownの出力

| 出力 | 中身 | 含める公開範囲 |
|---|---|---|
| 進行資料 | `2nd_hearing_overview.md` と同じ構成（目的、仮説、タイムテーブル、要約、質問） | すべて |
| 本人向けの要約 | 当日画面に出す要約 | `本人に見せる` だけ |
| 事前の依頼文 | 依頼文 | `本人に見せる` だけ |
| 提案用の整理 | 課題、データ、評価 | `提案に使う` だけ。対象者の名前を伏せることもできる |

出力したMarkdownは `data/exports/` にも保存します。

### 横断表示と評価表

AIは使わず、利用者が付けたテーマ、評価、ひも付けをもとに集計します（`app/analysis.py`）。

| 画面 | 内容 |
|---|---|
| 横断表示 | 対象者ごとの状況（回、仮説、課題、データ）。テーマごとの課題と、何人に共通するか |
| | 同じ名前の手法が複数の人の課題にひも付く解決策の候補。データがひも付いていない課題、確認済みでないデータ |
| 評価表と解決策 | 課題×観点の評価（◎3、○2、△1、×0点の合計で並べ替え）。セルを押して評価と理由を入力 |
| | 解決策の候補と評価の観点の追加・編集・削除。提案用の整理の出力 |

- 状態が「見送り」の課題は、横断表示と評価表から除きます（評価表は表示を切り替えられます）。
- 観点の名前を変えると、入力済みの評価も新しい名前に移ります。観点や課題を削除すると、その評価も削除します。
- 提案用の整理には、発言そのもの（本人の負担感）を含めません。名前を伏せる場合は、課題や評価の理由などの文章の中の名前（「石井さん」「石井」）も「メンバー1」などに置き換えます。
- 取り込んだ課題カード（計画書の「課題の仮説」）には、仮のテーマを付けています。

## 6. 既存資料の取り込み

`tools/import_existing.py` で、`002_hearing_supporter` の資料からCSVを作ります。

| 取り込み元 | 作るデータ |
|---|---|
| `terms.md` | 用語集（人名には誤認識の例を入れる。例：砂盃さん→イサイ、伊沢） |
| `hearing/isahai.md`、`hearing/ishii.md` | 対象者、第1回、発言 |
| `question/2nd_hearing_overview.md` | 第2回の目的、仮説、タイムテーブル、要約、質問 |
| `question/*_2nd_plan.md` | 事前の依頼文、解決策の候補（第7章）、評価の観点（第10章） |

- 別メンバーのまとめ（`6aec403…md`）は取り込みません。
- 第1回の文字起こしは推敲が済んでいるため、`推敲済み` として取り込みます。時刻の情報は残っていないので空欄です。
- 石井さんの第1回の通勤以降の発言は、`excluded=1`（分析の対象外）として取り込みます。
- 計画書と進行資料で内容が違う場合は、新しい進行資料を優先します。
- 取り込みは何度でもやり直せます。やり直すと `data/` の内容を作り直すので、前の内容は `backups/` に保存します。
  **ツールで編集を始めた後にやり直すと、編集した内容は消えます**（バックアップからは戻せます）。

## 7. 文字起こし

「文字起こしと推敲」の画面から、AzureのAI（`gpt-transcribe`）で文字起こしします（`app/transcribe.py`）。002_hearing_supporterで使った方法と同じです。

1. 音声を無音の位置で約6分ごとに分ける（モノラルのmp3に変換するので、mp3以外の音声や動画も扱える）
2. 分けたものを1つずつ `gpt-transcribe` に送る（呼び出しの間を21秒以上空ける）
3. 結果を**文ごとの発言**として保存する。発言者は空なので、推敲画面で付ける

- **実行前に**、音声の長さ、呼び出しの回数、目安の料金と時間を表示し、確認してから実行します。
  料金の目安は1分あたり0.0045〜0.006ドルで、公式の単価は未確認の概算です。
- 分けた音声と各回の結果は `data/transcribe_work/` に残します。途中で失敗しても、続きから再開できます。
  最初からやり直したいときは、その回のフォルダを削除します。
- すでに発言がある回で実行すると、発言を置き換えます（前の内容は `data/backups/` に保存）。
- 「用語集の用語をヒントとして渡す」を選ぶと、用語の一覧をモデルに渡します。固有名詞の精度が上がる可能性がありますが、効果は未確認です。
- 音声は日本国外（eastus2）で処理されます。
- 音声の分割には、`imageio-ffmpeg` に同梱のffmpegを使います（なければPATHのffmpeg）。利用者がffmpegをインストールする必要はありません。
  音声の長さは、`ffprobe` ではなくffmpegの出力から読み取ります。

### 推敲の流れ

1. 文字起こしを実行する（文ごとの発言ができる）
2. 時刻のボタンで音声を再生しながら、文ごとに発言者を選ぶ
3. 「続けて同じ発言者の発言をまとめる」で、発言者ごとにまとめる
4. 誤認識の候補（用語集の「誤認識されやすい表記」）を置き換え、文章を直す
5. 雑談などは「対象外」にし、確認した発言を「推敲済み」にする
6. 必要に応じて、発言を質問、仮説、課題にひも付ける

時刻は分けた音声の開始位置です（`gpt-transcribe` は文ごとの時刻を返さないため）。再生位置は目安になります。

## 8. 今後の拡張

### 動画から音声を取り出す

1. 利用者は動画や音声を `data/inbox/` に置く
2. ツールの画面に、`inbox/` のファイルが一覧で出る
3. 選んだファイルから、同梱のffmpegで音声を取り出してmp3にし、`audio/` に保存する
4. 7章の手順で文字起こしする

今も、`audio/` に置いた動画は文字起こしの時にmp3に変換するため、文字起こしはできます（推敲画面での再生は、ブラウザが対応する形式に限られます）。

### 発言者の自動判別

推敲で、発言ごとに発言者（聞き手、対象者）を付ける作業がいちばん手間がかかるため、これを自動にします。
Azure AI Speechの話者分離を使う案です（生成AIは使いません）。提供状況と料金は、取りかかる時点で確認します。

### そのほかのAIの機能

実際にツールを使ってみて、必要になったものから追加します。

| 機能 | 手法 | 生成AIを使うか |
|---|---|---|
| 用語や人名の候補の抽出 | キーフレーズ抽出、固有表現抽出。用語集や誤認識の候補に追加する | 使わない |
| 似た課題のまとめ | 埋め込みによる類似度の計算、クラスタリング。横断表示のテーマ付けを助ける | 使わない |
| 発言の分類（事実、感想、課題） | テキスト分類 | 学習データがなければ、生成AIのほうが現実的 |
| 要約や質問案の作成 | 生成AI | 使う |

- AzureのAIを使う機能は、文字起こしと同じように、実行の前に回数と料金の目安を出して確認してから実行します。
- 生成AIを使わない機能を中心にすると、このツール自体が「生成AI以外のAIの活用」の例になります。

## 9. exe化と配布

PyInstallerでexeにし、Pythonが入っていないPCでも使えるようにします。
配布するのは「exeとその部品のフォルダ」で、1つのexeファイルにはしません（起動が速く、ウイルス対策ソフトに止められにくいため）。

### 9.1 関係するファイル

| ファイル | 役割 |
|---|---|
| `run_app.py` | exeの入口。サーバを起動し、ブラウザで画面を開く |
| `hearing_tool.spec` | PyInstallerの設定。同梱するファイル（画面、設定の見本、ffmpeg）を指定する |
| `app/config.py` | exeで動いているときは、`config.json` と `data` をexeと同じフォルダから読む |

### 9.2 exeを作る（作る人のPCで1回）

`003_hearing_tool` フォルダで、PowerShellから実行します。

```powershell
# 1. パッケージを入れる（PyInstaller は exe を作る人だけが使うので requirements.txt には入れていない）
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m pip install pyinstaller

# 2. exe を作る（1分ほどかかる）
.\.venv\Scripts\pyinstaller.exe hearing_tool.spec --noconfirm
```

`dist\hearing_tool\` に次のものができます（合計で約140MB。うち約100MBは同梱のffmpeg）。

```text
dist\hearing_tool\
├── hearing_tool.exe   起動するファイル
└── _internal\         exe の部品（画面のファイル、Python、ffmpeg など）。消さない
```

- 途中の `Hidden import "tzdata" not found` という警告は、このツールでは使わない部品のため、無視して構いません。
- `dist\` と `build\` はGitの管理対象外です（ルートの `.gitignore` で除外済み）。
- コードを変えたら、もう一度 2. を実行して作り直します。

### 9.3 配布する

1. `dist\hearing_tool\` フォルダを**丸ごと**ZIPにして渡します。
   使い方の `manual.md` と `起動.bat` も、このフォルダに入れて一緒に渡します。
   **exeを作り直すと `dist\hearing_tool\` は作り直され、後から入れたファイルは消えます。** 控えが `others\` にあるので、作り直した後にコピーします。
2. 次のものは**ZIPに入れない**でください。

| 入れないもの | 理由 | 渡し方 |
|---|---|---|
| `data\` | 発言や個人の情報を含む | ツールの「入出力と設定」でCSVのZIPを書き出して渡す |
| `config.json` | 利用者ごとの設定（更新者の名前） | 受け取った人の初回起動で自動で作られる |
| `.env` | AzureのAPIキーを含む | 文字起こしを使う人にだけ、別の安全な方法で渡す |
| 音声や動画 | 大きく、録音を含む | ファイルを直接渡す |

### 9.4 受け取った人の使い方

1. ZIPを好きな場所に展開します（例：`C:\tools\hearing_tool\`）。
   OneDriveなど同期されるフォルダは、データの同期の衝突を避けるため、おすすめしません。
2. `起動.bat`（または `hearing_tool.exe`）をダブルクリックします。
   - 黒いウィンドウが開き、少し待つとブラウザで画面が開きます（開かなければ http://localhost:8000 を開く）。
   - 初回は、exeと同じフォルダに `config.json` と `data\` が作られます。
3. 「入出力と設定」で、更新者の名前を自分の名前にします。
4. ほかの人のデータを使うときは、「入出力と設定」でZIPを取り込みます。音声は `data\audio\` に置きます。
5. **終了するときは、黒いウィンドウを閉じます。** ブラウザを閉じただけでは終了しません。

文字起こしを使う人は、受け取った `.env` をexeと同じフォルダに置きます（`config.json` の `azure_env_file` の既定値が `./.env`）。
`.env` に必要な項目は `AZURE_OPENAI_ENDPOINT`、`AZURE_OPENAI_KEY`、`AZURE_TRANSCRIBE_MODEL` です。

展開後のフォルダは次のようになります。

```text
hearing_tool\
├── hearing_tool.exe
├── _internal\
├── config.json   初回起動で作られる
├── .env          文字起こしを使う人だけ置く
└── data\         初回起動で作られる（CSV、audio、exports、backups など）
```

### 9.5 新しい版に入れ替える

`hearing_tool.exe` と `_internal\` だけを新しいものに置き換えます。`config.json`、`.env`、`data\` はそのまま使えます。
念のため、入れ替える前に `data\` をコピーしておきます。

### 9.6 起動の引数

ショートカットのリンク先に付けて使えます。

| 引数 | 内容 |
|---|---|
| `--port 8001` | 8000番が使えないときに、別のポートで起動する |
| `--no-browser` | ブラウザを自動で開かない |

すでに起動しているときにもう一度ダブルクリックすると、新しく起動せずにブラウザで画面を開きます。

### 9.7 気をつけること

- **Windowsの警告：** 署名のないexeのため、初回に「WindowsによってPCが保護されました」と出ることがあります。「詳細情報」→「実行」で起動できます。社内のルールで実行が禁止されていないか、配布の前に確認してください。
- **ウイルス対策ソフト：** PyInstallerで作ったexeは、誤って検知されることがあります。止められた場合は、社内の担当者に相談してください。
- **同梱のffmpeg：** `imageio-ffmpeg` に含まれるffmpegを同梱しています。社内で使う範囲では問題にならない想定ですが、社外に配布する場合はffmpegのライセンスを確認してください。
- **既存資料の取り込み：** `tools/import_existing.py` はexeに含めていません。002_hearing_supporterの資料の取り込みは開発環境で行い、できたデータをZIPで渡します。
- **作るPCと使うPC：** Windows（64bit）で作ったexeは、Windows（64bit）でだけ動きます。
- **開発環境での起動：** exeにしなくても、`.\.venv\Scripts\python.exe run_app.py` で同じように起動できます（ブラウザも自動で開く）。
