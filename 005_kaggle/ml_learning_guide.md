## 2. 機械学習の問題タイプ

まず「自分が解いているのはどの種類の問題か」を正確に把握することが重要です。  
問題の種類によって、モデル・評価指標・アプローチが大きく変わります。

### 2-1. 問題タイプの分類

| 問題タイプ | 出力の種類 | 具体例 | 主なモデル |
|---|---|---|---|
| **二値分類** | 0 or 1 | 生存/死亡、災害/非災害 | LightGBM、RandomForest、BERT |
| **多クラス分類** | 0〜N のどれか | 数字(0〜9)の認識、灌漑レベル | LightGBM、CNN |
| **回帰** | 連続値 | 住宅価格、店舗売上 | LightGBM、Ridge回帰 |
| **時系列回帰** | 連続値（時間順） | 将来の売上予測 | LightGBM + TimeSeriesSplit |
| **画像分類** | カテゴリ | 手書き文字の認識 | CNN（畳み込みニューラルネットワーク） |
| **テキスト分類** | カテゴリ | ツイートの分類 | TF-IDF + ロジスティック回帰、BERT |

### 2-2. データタイプの確認

問題タイプと同様に、扱うデータの種類も重要です。

```
テーブルデータ（数値・カテゴリの表形式）
  → LightGBM・XGBoost・CatBoost が強い

時系列データ（日付・時刻つきのテーブルデータ）
  → LightGBM + TimeSeriesSplit を使う

画像データ（ピクセル値の配列）
  → CNN（畳み込みニューラルネットワーク）を使う

テキストデータ（文章・単語の列）
  → TF-IDF（統計的手法）または BERT（深層学習）を使う
```

## 3. 精度改善の基本サイクル

### 3-1. 精度改善の2つのアプローチ

どの問題でも、精度改善は以下の2方向から行います。

| アプローチ | 内容 | 具体的な手法 |
|---|---|---|
| **データ側の改善** | 特徴量の追加・加工・選択 | 特徴量エンジニアリング、欠損値処理 |
| **モデル側の改善** | アルゴリズムの変更・パラメータの最適化 | モデル変更、ハイパーパラメータ探索 |

> **重要な原則**
> - まずシンプルなモデルで**ベースライン**を確立する
> - 変更は**1つずつ**行い、各変更の効果を測定する
> - 「複雑にすれば良くなる」とは限らない

### 3-2. 精度改善のサイクル

```
①  EDA でデータを理解する
    ↓
②  シンプルなベースラインを作る
    ↓
③  仮説を立てる（「この特徴量を追加すれば良くなるはず」等）
    ↓
④  実装して CV スコアを測定する
    ↓
⑤  改善した → 採用。改善しなかった → 却下。
    ↓
⑥  Kaggle に提出して実際のスコアを確認する
    ↓
⑦  CV スコアと提出スコアに大きな差がある
    → データリーク・過学習を疑う
    ↓
⑧  ① に戻る
```

> **最も大切なこと**  
> 「なぜこの手法を使うのか」「何の問題を解決しようとしているのか」を  
> 常に意識しながら改善を進めること。手法を目的にしないこと。

## 4. 評価指標の種類と選び方

評価指標とは「モデルの精度をどう測るか」の基準です。  
問題の種類によって使うべき指標が異なります。

### 4-1. 分類問題の評価指標

#### Accuracy（正解率）

```
Accuracy = 正解した件数 / 全件数

例: 100件中 80件正解 → Accuracy = 0.80
```

**注意**: クラスが極端に偏っている場合は使えない。  
例: 「99%が正常」なデータでは、「全部正常」と予測するだけで Accuracy=0.99 になってしまう。

#### Balanced Accuracy（バランス正解率）

クラスが偏っている（不均衡な）場合に使う指標。各クラスの正解率を平均する。

```
例: Low=58.7%, Medium=37.9%, High=3.3% のデータで
  「全部 Low と予測」 → Accuracy=0.587、 Balanced Accuracy≒0.33（低い値になる）
```

**使うとき**: クラス数が不均衡（例: High クラスが 3.3% しかない）なコンペ

#### F1スコア

```
F1 = 2 × (Precision × Recall) / (Precision + Recall)

Precision（適合率）= TP / (TP + FP)
  → 「災害と予測したうち、本当に災害だった割合」

Recall（再現率）= TP / (TP + FN)
  → 「本当に災害のうち、正しく検知できた割合」
```

「見逃しを減らす（Recall↑）」と「誤報を減らす（Precision↑）」の両立が重要。

#### ROC-AUC（Receiver Operating Characteristic - Area Under the Curve）

```
AUC = 0 と 1 のサンプルをランダムに1件ずつ取り出したとき、
      モデルが正しく「1の方が高い確率」と予測できる確率

AUC = 0.5: ランダム予測と同じ（全く意味がない）
AUC = 1.0: 完璧な予測
```

ROC曲線は「閾値を 0→1 に動かしたとき、True Positive Rate と False Positive Rate がどう変化するか」を表した曲線です。  
AUC はその曲線の下の面積（Area Under the Curve）で、曲線が左上に張り出すほど（AUC が 1 に近いほど）優れたモデルです。  
閾値（何%以上を陽性とするか）に依存しない指標。確率値をそのまま提出できる。

### 4-2. 回帰問題の評価指標

#### MAE（Mean Absolute Error: 平均絶対誤差）

```
MAE = Σ|予測値 - 実際の値| / n

→ 「平均して何単位外れるか」を直感的に表せる
   例: MAE=14.27L → 平均して 14.27L 外れる
```

#### RMSE（Root Mean Squared Error: 平均二乗誤差の平方根）

```
RMSE = √( Σ(予測値 - 実際の値)² / n )

→ 外れ値（大きく外れた予測）に敏感。単位が元の値と同じになる。
```

#### RMSLE（Root Mean Squared Log Error）

```
RMSLE = √( Σ(log(1 + 予測値) - log(1 + 実際の値))² / n )

→ 大きな値の誤差と小さな値の誤差を同じ重みで評価する
→ log1p(目的変数) を学習すれば RMSE ≈ RMSLE が成立する
```

#### RMSPE（Root Mean Square Percentage Error）

```
RMSPE = √( Σ((実際の値 - 予測値) / 実際の値)² / n )

→ 絶対誤差ではなく「割合誤差」で評価する
→ 売上が少ない店舗の精度も同等に重視される
```

## 5. ステップ1: データを理解する（EDA）

EDA（Exploratory Data Analysis: 探索的データ分析）とは、  
グラフや集計を使ってデータの構造・傾向・関係性を把握する作業です。

### 5-1. なぜ EDA から始めるのか

直感的・経験的な知識がない問題では、**まずデータそのものに語らせる**ことが出発点になります。  
「どの特徴量が重要か」「どんな前処理が必要か」を事前に把握することで、  
無駄な試行錯誤を減らせます。

### 5-2. EDA でやること

#### ① 目的変数の分布確認

まず「予測したいもの」の分布を確認します。

```python
# クラス分布の確認（分類）
df['target'].value_counts()

# 分布の形の確認（回帰）
df['SalePrice'].hist(bins=50)
```

| 確認すること | 判断のポイント |
|---|---|
| クラスが偏っていないか | 偏り大 → Balanced Accuracy や F1 を使う |
| 分布が歪んでいないか | 右歪み → 対数変換を検討する |
| 欠損値はないか | 欠損あり → 補完が必要 |

#### ② 特徴量と目的変数の関係確認

どの特徴量が目的変数と関係しているかを調べます。

```python
# カテゴリ列ごとに目的変数の平均を確認
df.groupby('CryoSleep')['Transported'].mean()
# → カテゴリ間の差が大きいほど重要な特徴量の候補

# 相関係数で数値との関係を確認
df[num_cols].corr()['target'].sort_values()
```

#### ③ Feature Importance（特徴量重要度）

最も実用的な特徴量の評価手法。全特徴量でモデルを学習させ、  
**モデル自身に「どの列が重要か」を判定させます**。

```python
model = RandomForestClassifier(n_estimators=100, random_state=42)
model.fit(X_train, y_train)

importances = pd.Series(model.feature_importances_, index=X_train.columns)
importances.sort_values(ascending=False).head(10)
```

**なぜ有効か**: 線形の相関係数と異なり、複雑な交互作用や非線形な関係も反映されます。

### 5-3. EDA で使う3つの手法の比較

```
手法1: 統計的探索（カテゴリ別集計・分布比較・相関係数）
  → 直感的にわかりやすいが、複雑な関係は見えない

手法2: 統計的検定（t検定・カイ二乗検定）
  → 「本当に関係があるか」を数値で判断できる

手法3: モデルベースの重要度（Feature Importance）
  → 非線形・複雑な交互作用も捉えられる。最も実用的
```

### 5-4. ドメイン知識の収集

表形式データでは、**データの背景にある現実を理解している人が有利**です。

```
モデルは「数値のパターン」しか見えない
ドメイン知識があると「この数値は何を意味するか」が分かる
→ 効果的な特徴量エンジニアリングのアイデアが浮かぶ
→ おかしな予測の原因に気づける
```

> **ドメイン知識収集の進め方**
> 1. データの各カラムが「現実の何を意味するか」を調べる
> 2. 目的変数との関係を「常識」から予想する
> 3. 実際にデータで確認する（`groupby` での集計など）
> 4. 予想と一致する特徴量 → 信頼できる特徴量候補
> 5. 予想と外れた特徴量 → なぜ違うか考えることで深い理解が生まれる

## 6. ステップ2: ベースラインモデルを作る

### 6-1. なぜベースラインが重要なのか

> これ以降のすべての改善は「ベースラインと比べて良くなっているか」を基準に判断します。  
> ベースラインがないと、改善の効果を測定できません。

### 6-2. ベースラインの作り方

**原則**: 最小限の特徴量 × シンプルなモデルから始める。

```python
# 分類の例（タイタニック）
features = ["Pclass", "Sex", "SibSp", "Parch"]  # 直感的に重要な4列
model = RandomForestClassifier(n_estimators=100, max_depth=5, random_state=1)
model.fit(X, y)

# 回帰の例（住宅価格）
features = ["LotArea", "YearRemodAdd"]  # 直感的に重要な2列
model = RandomForestRegressor(n_estimators=100, random_state=1)
model.fit(X, y)
```

**なぜ少ない特徴量から始めるのか**:

```
特徴量が少ない → 過学習しにくい → 安定したベースラインになる
特徴量が多い  → 一見スコアが高く見えても過学習の可能性がある
```

### 6-3. ベースライン作成時のチェックポイント

```
□ CV スコア（交差検証のスコア）を計算したか
□ 学習データのスコア（Train スコア）と CV スコアを比較したか
□ Kaggle に提出してリーダーボードスコアを確認したか
□ CV スコアと LB スコアの差は小さいか（大きい場合はデータリークや過学習を疑う）
```

## 7. ステップ3: 特徴量エンジニアリング

特徴量エンジニアリングとは、**元のデータに含まれる情報を「別の角度から表現」する**ことで、  
モデルが学習しやすい新しい特徴量を作る作業です。

### 7-1. 特徴量エンジニアリングの基本的な考え方

```
「このデータの背景にある現実」を考える

例1: Name 列に "Mr. Smith" という形式で敬称が含まれている
  → 敬称は年齢・性別・社会的地位を反映している
  → Title として抽出すれば有用な情報になる

例2: LotArea は 1,000〜200,000 平方フィートと幅が広い
  → 「面積が倍になっても価値は倍にならない」
  → 対数変換で「面積増加の効果が逓減する」現実を反映できる
```

### 7-2. 特徴量の種類と作り方

#### 既存列からの新列作成

```python
# 合計・比率
df["FamilySize"]    = df["SibSp"] + df["Parch"] + 1
df["attendance_rate"] = df["total_attendance"] / df["business_days"]

# 二値フラグ
df["IsAlone"]   = (df["FamilySize"] == 1).astype(int)
df["HasCabin"]  = df["Cabin"].notna().astype(int)

# 文字列の分割・抽出
df["Title"]   = df["Name"].str.extract(r" ([A-Za-z]+)\.")  # タイタニック
cabin_split   = df["Cabin"].str.split("/", expand=True)
df["Deck"]    = cabin_split[0]  # 宇宙船タイタニック
```

#### 数値変換

```python
# 対数変換（分布が歪んでいるとき）
df["LotArea_log"]    = np.log1p(df["LotArea"])
df["TyreLife_sq"]    = df["TyreLife"] ** 2  # 非線形性を表現（二乗項）
df["TyreLife_sqrt"]  = np.sqrt(df["TyreLife"])

# 経過時間・割合への変換
df["YearsSinceRemod"]   = 2007 - df["YearRemodAdd"]
df["TyreLife_x_Dur"]    = df["TyreLife"] / df["Compound_Dur"]
```

#### 交互作用特徴量

2つの特徴量の組み合わせで生まれるパターンを捉えます。

```python
# 数値 × 数値
df["Temp_x_Wind"]   = df["Temperature_C"] * df["Wind_Speed_kmh"]
df["Area_x_Remod"]  = df["LotArea"] * df["YearRemodAdd"]

# カテゴリ × カテゴリ
df["Cryo_x_Planet"] = df["CryoSleep"].astype(str) + "_" + df["HomePlanet"]
# → "True_Europa", "False_Earth" など 6 パターンが生成される
```

**交互作用特徴量が有効な理由**:

```
LightGBM などの決定木モデルは特徴量を1つずつ個別に参照して分割する。
2つの特徴量の組み合わせから生まれるパターンを検出するには多くの分岐が必要。
交互作用特徴量を作ると、1回の分岐で同じ情報を表現できる。
```

#### 時系列固有の特徴量（時系列データの場合）

```python
# 日付から周期的な特徴量を作成
df["year"]       = df["date"].dt.year
df["month"]      = df["date"].dt.month
df["dayofweek"]  = df["date"].dt.dayofweek
df["is_weekend"] = (df["dayofweek"] >= 5).astype(int)
df["is_salary_day"] = df["day"].isin([15, 28, 29, 30, 31]).astype(int)

# ラグ特徴量: N日前の値を特徴量として使う
df["sales_lag_16"] = df.groupby(["store_nbr", "family"])["sales"].shift(16)
df["sales_lag_365"] = df.groupby(["store_nbr", "family"])["sales"].shift(365)

# ローリング統計量: 直近N日間の平均・標準偏差
df["sales_roll7_mean"] = df.groupby(...)["sales"].shift(16).rolling(7).mean()
```

> **ラグ特徴量のリーク防止**  
> テストデータが N 日間の場合、`lag >= N + 1` でないとデータリークが発生する。  
> テスト期間が 15 日間なら `lag >= 16` にする。

### 7-3. 特徴量の逐次追加（重要）

全部の特徴量を一度に追加するのではなく、**1つずつ追加して CV スコアが改善した場合のみ採用**します。

```python
base_features = ["Pclass", "Sex", "SibSp", "Parch"]

for feat in candidates:
    score = cv_score(selected_features + [feat])  # 追加した場合のスコアを測定
    if score > base_score:
        selected_features.append(feat)  # 改善 → 採用
        base_score = score
    # 改善しなかった → 採用しない
```

**このアプローチで学べること**:
- 「特徴量が多いほど良い」は間違い
- 各特徴量が「本当に予測に貢献しているか」をデータで確認することが重要
- 直感や理論で「使えそう」と思った特徴量でも、データが答えを持っている

### 7-4. 目的変数の対数変換（回帰問題）

住宅価格や売上など「右に歪んだ分布」を持つ目的変数には対数変換が有効です。

```
変換前: 分布が右歪み（一部の超高額物件が極端に高い）
  → RMSE は外れ値の誤差を二乗するため、外れ値の影響が過大評価される

変換後: log(価格) が正規分布に近くなる
  → モデルが全体的に学習しやすくなる
```

```python
# 学習時: SalePrice を対数変換してから学習
y = np.log1p(train_data["SalePrice"])   # log(1 + SalePrice)
model.fit(X, y)

# 予測時: 対数変換を元に戻す
predictions = np.expm1(model.predict(X_test))  # exp(予測値) - 1
```

| 関数 | 計算式 | 用途 |
|---|---|---|
| `np.log1p(x)` | `log(1 + x)` | 学習前に目的変数を変換 |
| `np.expm1(x)` | `exp(x) - 1` | 予測後に元のスケールへ逆変換 |

## 8. ステップ4: 欠損値処理

機械学習モデルは欠損値（NaN）をそのまま扱えない（一部例外あり）ため、  
何らかの値で補完する必要があります。

### 8-1. 補完方法の選び方

| 方法 | 使う状況 | 注意 |
|---|---|---|
| 0で補完 | 「設備なし」を意味する欠損（例: 冷凍睡眠中のアメニティ支出） | ドメイン知識が必要 |
| 中央値補完 | 数値列の一般的な欠損 | 外れ値に強い |
| 平均値補完 | 数値列の一般的な欠損 | 外れ値に弱い |
| 最頻値補完 | カテゴリ列の一般的な欠損 | 情報量は失われる |
| グループ内補完 | 同グループ（家族など）なら同じ値の可能性が高い列 | より正確な補完 |

### 8-2. ドメイン知識を使った補完

```python
# 例: 冷凍睡眠中はアメニティを物理的に使えない → 支出は必ず0
cryo_true = df["CryoSleep"] == True
for col in AMENITIES:
    df.loc[cryo_true, col] = df.loc[cryo_true, col].fillna(0)
# 全体中央値で補完するより正確な値になる
```

### 8-3. グループ内補完

```python
def group_fill(df, col):
    # 同グループ内の既知の値で前後補完
    df[col] = df.groupby("Group")[col].transform(lambda x: x.ffill().bfill())
    return df

# 例: グループ "0003" に 3人の乗客
# 0003_01: HomePlanet = "Europa"
# 0003_02: HomePlanet = NaN（欠損）← "Europa" で補完
# 0003_03: HomePlanet = "Europa"
```

### 8-4. 欠損補完の重要な原則

> 補完に使う統計量（平均・中央値・最頻値など）は**常に train データだけで計算し**、  
> その値を test データに適用する（データリーク防止）。

```python
# 正しい方法
median_value = train_data["Age"].median()  # train だけで計算
train_data["Age"] = train_data["Age"].fillna(median_value)
test_data["Age"]  = test_data["Age"].fillna(median_value)  # 同じ値を適用
```

## 9. ステップ5: モデルの選択と切り替え

### 9-1. モデル選択の基本方針

```
データの種類によって適切なモデルが異なる:

テーブルデータ  → LightGBM / XGBoost / CatBoost（勾配ブースティング）
画像データ     → CNN（畳み込みニューラルネットワーク）
テキストデータ  → TF-IDF + ロジスティック回帰 または BERT
時系列データ   → LightGBM + TimeSeriesSplit
```

### 9-2. 勾配ブースティング系モデル

テーブルデータで最も実績があるのが勾配ブースティング系モデルです。

```
学習データ → [木1] → 誤差 → [木2（誤差を修正）] → 誤差 → [木3] → ... → 最終予測

RandomForest: 複数の木を「独立して」学習し、多数決で予測
LightGBM:    複数の木が「前の木の失敗を引き継いで」順番に学習（勾配ブースティング）
```

| モデル | 特徴 | 主な使いどころ |
|---|---|---|
| RandomForest | シンプル・頑健・解釈しやすい | ベースライン作成、Feature Importance 確認 |
| **LightGBM** | 高速・大規模データに強い・Kaggle で最実績 | テーブルデータの本命 |
| XGBoost | 精度が高い・LightGBM と相補的 | LightGBM とのアンサンブル |
| CatBoost | カテゴリ変数に強い | カーディナリティの高いカテゴリ変数がある場合 |

### 9-3. CNN（画像データの場合）

LightGBM などの機械学習モデルは「784個の数値を**独立した特徴量**」として扱うため、  
隣り合うピクセルが形成する「縦線・横線・曲線」などのパターンを学習できません。  
CNN はこの空間的な構造を学習できます。

```
CNN の3つの主要な処理:

1. 畳み込み層（Conv2D）
   小さな「フィルター」をスライドさせて画像内のパターンを検出
   → 縦線・横線・斜線など単純なパターンを学習

2. プーリング層（MaxPooling2D）
   特徴マップを縮小し、位置の微小なズレに頑健にする
   → 数字が少し傾いていても認識できるようになる

3. Dropout（過学習防止）
   学習中にランダムにニューロンを無効化
   → 特定のパターンへの依存を防ぐ
```

### 9-4. BERT（テキストデータの場合）

**BERT（Bidirectional Encoder Representations from Transformers）** は Google が開発した大規模な事前学習済み言語モデルです。  
大量のテキストコーパスで「文脈を双方向に読む」訓練を事前に済ませており、  
手元のタスク向けに少量データで追加学習（ファインチューニング）するだけで高精度を発揮します。

```
事前学習（Pre-training）: 大量のテキストで「穴埋め問題」と「文の順序予測」を学習済み
    ↓
ファインチューニング（Fine-tuning）: 手元のラベルデータで出力層だけ追加学習
→ 少ないデータでも高精度を出せる理由はここにある
```

TF-IDF の根本的な限界:

```
"I'm on fire！" （比喩）
"The building is on fire." （本物の災害）

→ TF-IDF はどちらも "fire" が含まれている → 同じように扱う
→ BERT は前後の文脈を双方向に読んで区別できる
```

| 比較項目 | TF-IDF | BERT |
|---|---|---|
| 単語の理解 | 出現頻度（文脈なし） | 前後の文脈を双方向に考慮 |
| 学習速度 | 数秒 | 数時間（CPU）/ 数十分（GPU） |
| 精度 | 中程度 | 高精度 |
| 必要データ量 | 少量でも動く | ファインチューニングに数百件以上あると安定 |

> **選択の指針**: まず TF-IDF でベースラインを作り、精度の上限が見えてから BERT に移行する。  
> Twitter / SNS テキストには口語・略語に強い `vinai/bertweet-base` が特に有効。

### 9-5. クラス不均衡への対処

```
クラスが偏っているとき（例: High クラスが 3.3%）:

対策1（まず試す）: class_weight='balanced' / is_unbalance=True
  → データを変えずにモデル側で自動調整。実装が簡単。

対策2: SMOTE などのオーバーサンプリング
  → 少数クラスを人工的に増やす。大規模データでは時間がかかる。

原則: 試行コストの低い方法から順番に試す。
```

## 10. ステップ6: 交差検証（CV）

### 10-1. なぜ交差検証が必要なのか

単純に「訓練データでスコアを測る」と、モデルが学習データを暗記しているだけでも高スコアになります（過学習）。  
交差検証は「未知データでどれくらい精度が出るか」を正直に推定するための手法です。

### 10-2. 交差検証の種類

#### K-Fold CV（基本的な交差検証）

```
データ全体 [1][2][3][4][5]

1回目: [検証][学習][学習][学習][学習]
2回目: [学習][検証][学習][学習][学習]
...（5回繰り返す）

→ 5回の平均スコアを「真の精度の推定値」とする
```

#### StratifiedKFold（分類問題で使う）

```
通常の KFold では各 fold のクラス比率が偶然偏ることがある。
StratifiedKFold は各 fold のクラス比率を元のデータと同じに保証する。

→ クラス不均衡がある場合は必須
→ 時系列以外の分類問題では基本的にこれを使う
```

#### TimeSeriesSplit（時系列データで使う）

```
通常の k-fold（NG）:
  fold1: [検証][学習][学習][学習][学習]  ← 未来のデータで過去を予測 → 不正

TimeSeriesSplit（OK）:
  fold1: [学習] → [検証]
  fold2: [学習][学習] → [検証]
  fold3: [学習][学習][学習] → [検証]
  → 常に「過去で未来を予測」する正しい評価
```

> **重要**: 時系列データに通常の k-fold を使うと、「未来のデータで過去を学習」することになり、  
> 実際のテスト環境（未来の予測）とは全く異なる条件で評価されてしまう。

#### LOO-CV（Leave-One-Out Cross Validation）（データが少ない場合）

```
1件だけ除いてモデルを学習 → 除いた1件を予測 → 全件分繰り返す

→ データが10〜20件程度の場合に有効
→ k-fold では「2件で検証」という不安定な状況を避けられる
→ n件のデータがあれば n回学習するため、計算コストは k-fold より高い
```

#### Nested CV（モデル選択と評価を同時に行う場合）

```
外側CV（cross_val_score）: 汎化性能の評価
  └─ 内側CV（RandomizedSearchCV）: ハイパーパラメータ探索

→ パラメータ選択に使ったデータで評価しないため、スコアが正直になる
```

```python
inner_cv = RandomizedSearchCV(estimator, param_dist, n_iter=100, cv=5)
outer_scores = cross_val_score(inner_cv, X, y, cv=5, scoring="accuracy")
# outer_scores = バイアスのない汎化性能の推定
```

> **注意**: Nested CV のスコアは通常の CV より低く出る場合があります。  
> これは「精度が下がった」のではなく「より正直なスコアになった」ということです。

### 10-3. OOF（Out-of-Fold）予測

OOF とは、**各サンプルが「検証データ」だったときの予測値を fold をまたいで集めたもの**です。

```
fold1: [学習][学習][学習][学習][検証] → 検証データ分の予測値を記録
fold2: [学習][学習][学習][検証][学習] → 検証データ分の予測値を記録
fold3: [学習][学習][検証][学習][学習] → 検証データ分の予測値を記録
...
→ 全 fold が終わると、学習データ全件分の「未知データに対する予測値」が揃う
  これが OOF 予測（Out-of-Fold predictions）
```

**OOF が重要な理由**:
- 各サンプルは「自分が学習に使われていないモデル」で予測されるため、データリークがない
- `accuracy_score(y, oof_probs.argmax(axis=1))` が「正直な精度推定値」になる
- アンサンブルの重み最適化にも使える（12-4節参照）

```python
oof_probs  = np.zeros((len(X), n_classes))
test_probs = np.zeros((len(X_test), n_classes))

for fold, (tr_idx, val_idx) in enumerate(skf.split(X, y), 1):
    # 学習
    model.fit(X[tr_idx], y[tr_idx])
    # 検証データの予測を OOF に記録（このサンプルは学習に使っていない）
    oof_probs[val_idx] = model.predict_proba(X[val_idx])
    # テスト予測は fold 数で割って平均
    test_probs += model.predict_proba(X_test) / n_folds

# OOF スコアが「データリークのない正直な精度推定値」
oof_score = accuracy_score(y, oof_probs.argmax(axis=1))
```

## 11. ステップ7: ハイパーパラメータ最適化

### 11-1. ハイパーパラメータとは

モデルの「設定値」のこと。たとえば `max_depth=5`・`learning_rate=0.05` がこれにあたります。  
適切な値はデータによって異なるため、試行錯誤で探す必要があります。

### 11-2. GridSearchCV

指定したパラメータの**全組み合わせ**を試す手法。

```
n_estimators: [100, 200]  × 2通り
max_depth:    [3, 4, 5]   × 3通り
learning_rate:[0.05, 0.1] × 2通り
─────────────────────────────────
合計: 12通りを全て試す → 最良の組み合わせを採用
```

**問題点**: パラメータが増えると組み合わせが爆発する。

```
6つのパラメータ × 各5通り = 5^6 = 15,625通り × 5-fold = 78,125回の学習
```

### 11-3. RandomizedSearchCV

全組み合わせを試す代わりに、**確率分布からランダムにサンプリング**する手法。

```python
from scipy.stats import randint, uniform

param_dist = {
    "n_estimators":  randint(100, 600),    # 100〜599 の整数から無作為抽出
    "learning_rate": uniform(0.01, 0.30),  # 0.01〜0.30 の実数から無作為抽出
}
search = RandomizedSearchCV(model, param_dist, n_iter=100, cv=5)
```

- GridSearch では「指定した値の中でのベスト」しか見つけられない
- RandomizedSearch では「連続した範囲の中」から探せるため、より良い値を見つけやすい

### 11-4. Optuna（ベイズ最適化）

「これまでの結果から良さそうな場所を優先的に探索」する手法。  
ランダムサーチより効率的に最適解に近づけます。

```python
import optuna

def objective(trial):
    params = {
        "num_leaves":      trial.suggest_int("num_leaves", 31, 511),
        "learning_rate":   trial.suggest_float("learning_rate", 0.005, 0.1, log=True),
        "lambda_l1":       trial.suggest_float("lambda_l1", 0.001, 10, log=True),
    }
    model = lgb.LGBMClassifier(**params)
    score = cross_val_score(model, X, y, cv=3).mean()
    return score

study = optuna.create_study(direction="maximize")
study.optimize(objective, n_trials=50)
print(study.best_params)
```

**対数スケールで探索する理由**:

```
learning_rate の場合:
  線形: 0.005, 0.010, 0.015, ..., 0.100（均等な間隔）
  対数: 0.005, 0.010, 0.020, 0.040, 0.080（比率が均等）

  0.005 → 0.010 の変化（×2倍）と
  0.050 → 0.100 の変化（×2倍）は同じ「大きさの変化」
  → 対数スケールの方が自然な探索ができる
```

### 11-5. ハイパーパラメータと効果の関係

| パラメータ | 大きくすると | 小さくすると |
|---|---|---|
| `learning_rate` | 学習が粗くなる（速い） | 丁寧に学習（遅いが精度↑） |
| `num_leaves` / `max_depth` | 複雑なモデル（過学習リスク↑） | シンプルなモデル |
| `lambda_l1` / `lambda_l2` | 正則化強い（過学習抑制） | 正則化弱い |
| `min_child_samples` | 過学習を抑制 | 細かい分岐が増える |

## 12. ステップ8: アンサンブル

### 12-1. アンサンブルとは

複数のモデルの予測を組み合わせて最終予測を出す手法です。  
「多数決」に近い考え方で、1つのモデルが間違えても他のモデルで補正できます。

**なぜアンサンブルが効くのか**:

```
複数のモデルはそれぞれ異なるアルゴリズムで学習するため、
「異なる種類のエラーを犯す」
→ 多数決を取ることで、あるモデルのエラーが他のモデルによって打ち消される

効果を最大化するには:
  相関が低い（異なるタイプの）モデルを組み合わせるほど効果的
  各モデルを十分に調整した上でアンサンブルすること
```

### 12-2. ソフト投票（分類）

各モデルが出力する「予測確率」を平均して最終判定する。

```
RandomForest → 生存確率 0.65 ─┐
XGBoost      → 生存確率 0.72 ─┼─ 平均 0.68 → 生存（0.68 > 0.5）
LightGBM     → 生存確率 0.67 ─┘
```

```python
voting = VotingClassifier(
    estimators=[("rf", tuned_rf), ("xgb", tuned_xgb), ("lgbm", tuned_lgbm)],
    voting="soft",  # 予測確率の平均で判定（ハード投票より精度が高いことが多い）
)
```

### 12-3. 平均アンサンブル（回帰）

```
RandomForest → 予測価格 220,000 ─┐
XGBoost      → 予測価格 215,000 ─┼─ 平均 217,000 → 最終予測
LightGBM     → 予測価格 216,000 ─┘
```

```python
regressor = VotingRegressor(
    estimators=[("rf", tuned_rf), ("xgb", tuned_xgb), ("lgbm", tuned_lgbm)]
)
```

### 12-4. OOF アンサンブルの重み最適化

```python
# OOF 予測を使って最適な混合比率を探索
for w in np.linspace(0, 1, 101):
    oof_blend = w * oof_lgbm + (1 - w) * oof_catboost
    auc = roc_auc_score(y, oof_blend)
    if auc > best_auc:
        best_w = w
        best_auc = auc
```

## 13. よくある失敗とその対処法

### 13-1. 過学習（Overfitting）

**症状**: 学習データでは高精度、テストデータでは低精度。

```
理想的なモデル: 「データの本質的なパターン」を学習する
過学習したモデル: 「学習データ特有のノイズ」まで覚えてしまう

判断: Train スコア >> CV スコア （差が 0.05 以上ならば要注意）
```

| 対処法 | 効果 | 実装 |
|---|---|---|
| 特徴量を減らす | ★☆☆ | 逐次追加で CVスコアが上がるものだけ使う |
| 正則化を強くする | ★☆☆ | `lambda_l1`, `lambda_l2` を増やす |
| Early Stopping | ★★☆ | 検証スコアが改善しなくなったら停止 |
| Dropout（NN） | ★★☆ | ランダムにニューロンを無効化 |
| データを増やす | ★★★ | 外部データの追加、データ拡張（画像） |

### 13-2. データリーク（Data Leakage）

**症状**: CV スコアは高いのに Kaggle の提出スコアが低い。

```
データリークとは: テストデータの情報が「前処理の段階で」学習に混入すること。

例1: 欠損補完で全データ（train+test）の中央値を計算してしまった
例2: タイタニックの Title の Rare 判定を train+test を結合して行っていた
例3: ラグ特徴量でテスト期間内のデータを参照してしまった
```

**防ぎ方**:

```python
# NG: test の情報を使って補完
median_all = pd.concat([train, test])["Age"].median()

# OK: train のみで計算し、test に同じ値を適用
median_train = train["Age"].median()
train["Age"] = train["Age"].fillna(median_train)
test["Age"]  = test["Age"].fillna(median_train)
```

### 13-3. モデル選択バイアス

**症状**: GridSearchCV でチューニング後のスコアが楽観的すぎる（Kaggle 提出で下がる）。

```
問題: パラメータ選択 と 性能評価 に同じデータを使っている
結果: 「良く見えるモデルを選ぶ」という行為自体が、評価スコアを楽観的にする
```

**解決**: Nested CV を使って評価とチューニングを別データで行う。

### 13-4. 特徴量を増やしたら精度が下がった

**原因**: 過学習。特にデータが少ない場合に起こりやすい。

```
学習サンプルが 10〜20件で特徴量を増やすと:
  LOO-CVのMAEを見ながら試してみると、
  特徴量を追加するとむしろ精度が下がるケースが多い
```

**教訓**:

> 「データが少ないときは、特徴量を増やすよりデータを増やすことを先に考えるべき」  
> 「入力がシンプルな問題には、シンプルなモデルが合っている」

### 13-5. CV スコアと提出スコアの乖離が大きい

```
正常なギャップ（~0.001 以下）:
  モデルが汎化できている証拠

ギャップが急拡大（>0.005）:
  以下のいずれかを疑う:
    1. データリーク
    2. 過学習
    3. 訓練・テストの分布ズレ
```

### 13-6. ラグ特徴量で精度が悪化した

**原因**: ラグ特徴量のNaN率が学習データとテストデータで大きく異なった。

```
例: sales_lag_365 は「1年前のデータ」が必要
    学習データの最初の1年はデータが存在しない → 全てNaN
    → 21.7% の行が NaN になり、補完値が「意味のない値」になった
```

**教訓**:
1. 特徴量追加前に NaN 率を必ず確認する
2. ラグ特徴量の NaN は「過去データが存在しない」という意味。中央値で補完することは誤情報を与えること。
3. train・test・CV fold で NaN 率が揃っているか確認する

## 14. 問題タイプ別ガイド

### 14-1. テーブルデータの分類・回帰

```
推奨手順:

① EDA: 目的変数の分布・クラス不均衡・欠損値・特徴量との関係を確認
  ↓
② LightGBM + StratifiedKFold でベースラインを作成
  ↓
③ 特徴量エンジニアリング: 交互作用・数値変換・ドメイン知識による新列
  ↓
④ Optuna でハイパーパラメータを最適化
  ↓
⑤ CatBoost など別モデルを追加してアンサンブル
```

**クラス不均衡がある場合の注意点**:
- 評価指標を Balanced Accuracy や F1 にする
- `class_weight='balanced'` や `is_unbalance=True` を設定する
- `StratifiedKFold` で各 fold のクラス比率を保つ

### 14-2. 時系列データ

```
テーブルデータとの主な違い:

1. CVには必ず TimeSeriesSplit を使う
   → 通常の k-fold は「未来で過去を学習」するため不正

2. ラグ特徴量はリーク防止に注意する
   → テスト期間 N 日間 → lag > N が必要

3. train+test を結合してからラグを計算する
   → test 単独で shift() しても過去データが参照できない

4. NaN率を必ず確認する
   → ラグ特徴量の NaN は「過去データなし」を意味する
```

### 14-3. 画像データ

```
推奨手順:

① LightGBM でベースラインを作成（ピクセル値をそのまま特徴量として使う）
  ↓
② CNN（畳み込みニューラルネットワーク）に移行
  → 画像の空間的パターンを段階的に学習できる
  ↓
③ データ拡張（回転・シフト・ズーム）で汎化性能を向上
  ↓
④ EarlyStopping + ReduceLROnPlateau で学習を自動コントロール
```

```python
# データ拡張の例（手書き数字なので上下反転は NG）
data_augmentation = keras.Sequential([
    layers.RandomRotation(0.08),        # ±8% 回転
    layers.RandomTranslation(0.1, 0.1), # 上下左右に ±10% シフト
    layers.RandomZoom(0.1),             # ±10% ズーム
    # layers.RandomFlip() は使わない（6 が 9 に見える等）
])
```

### 14-4. テキストデータ（NLP）

```
推奨手順:

① TF-IDF + ロジスティック回帰でベースラインを作成
  → テキストを数値に変換する基本を学ぶ
  ↓
② BERT（または問題に特化した事前学習モデル）にファインチューニング
  → 文脈を理解するモデルに移行
  ↓
③ K-Fold + OOF アンサンブルで安定化
```

**TF-IDF のデータリーク防止**:

```python
# Pipeline を使えばデータリークを防げる
pipeline = Pipeline([
    ("tfidf", TfidfVectorizer(...)),
    ("clf",   LogisticRegression(...)),
])
# → CV の各 fold で train データのみで TF-IDF を fit する
```

**モデル選択のポイント**:

| 使うべき事前学習モデル | 状況 |
|---|---|
| `distilbert-base-uncased` | 一般的なテキスト分類 |
| `vinai/bertweet-base` | Twitter / SNS のテキスト（略語・絵文字・口語） |
| `roberta-large` | より高精度が必要な場合（計算コスト大） |

## 15. 精度改善チェックリスト

### EDA・前処理

```
□ 目的変数の分布を確認した
  → 歪んでいれば対数変換を検討
  → クラスが偏っていれば Balanced Accuracy や F1 を使う

□ 欠損値の分布と意味を確認した
  → 意味のある補完（ドメイン知識）を検討した
  → 補完統計量は train データのみで計算した

□ 特徴量と目的変数の関係を確認した
  → カテゴリ別集計・相関係数・Feature Importance を使った
```

### モデリング

```
□ シンプルなベースラインを作り、CV スコアと LB スコアを確認した

□ Train スコアと CV スコアの差を確認した
  → 差が大きければ過学習を疑う

□ CV スコアと LB スコアの差を確認した
  → 差が大きければデータリークを疑う

□ 特徴量は1つずつ追加して CV スコアが改善した場合のみ採用した

□ 問題の種類に合った CV 手法を使った
  → 時系列: TimeSeriesSplit
  → それ以外の分類: StratifiedKFold
  → データが少ない: LOO-CV

□ ハイパーパラメータを Optuna などで最適化した

□ 異なる種類のモデルでアンサンブルを試みた
  → 各モデルを十分に調整した上でアンサンブルした
```

### 提出前の最終確認

```
□ OOF スコアと LB スコアのギャップが正常範囲内か確認した（~0.001 以下）

□ 時系列データの場合、ラグ特徴量の NaN 率を確認した

□ 提出ファイルのフォーマット（行数・列名）を確認した
```

## まとめ：機械学習改善で最も大切なこと

9つのコンペティションを通じて共通して学んだことを1つの言葉で表すとすれば：

> **「なぜこの手法を使うのか」「何の問題を解決しようとしているのか」を  
> 常に意識しながら改善を進めること。手法を目的にしないこと。**

精度改善は「凝ったモデルや多くの特徴量を試すこと」ではありません。  
「今手元にあるデータで何ができるか」「モデルはどんな情報を必要としているか」を  
起点に設計することが、最終的によい結果につながります。

また、失敗を恐れないことも重要です。  
過学習・データリーク・CV と LB のギャップという「よくある失敗」は、  
それ自体が機械学習の重要な概念を深く理解するための教材になります。
