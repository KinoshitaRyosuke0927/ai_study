# 住宅販売価格予測モデル 精度向上ガイド

機械学習初学者向けに、住宅販売価格を予測するモデルの精度を向上させるための考え方・手法・実践プロセスを時系列でまとめた学習教材です。

---

## はじめに：分類と回帰の違い

タイタニックの生存予測と、住宅価格予測では**問題の種類が異なります**。

| | タイタニック（分類） | 住宅価格（回帰） |
|---|---|---|
| 問題の種類 | 分類（Classification） | 回帰（Regression） |
| 出力 | カテゴリ（0 or 1） | 連続値（価格） |
| 評価指標 | Accuracy（正解率） | RMSE（平均二乗誤差の平方根） |
| 使うモデル | `Classifier` 系 | `Regressor` 系 |

### RMSE とは

> **RMSE（Root Mean Squared Error）**  
> 予測値と実際の値の差（誤差）を二乗して平均し、平方根を取った値。  
> 単位が元の値（ドル）と同じになるため直感的に解釈しやすい。

```
誤差  = 予測価格 - 実際の価格
RMSE = √( Σ(誤差²) / n )

→ RMSE が小さいほど予測が正確
```

> **精度改善の基本原則**（回帰・分類共通）
> - まずシンプルなモデルでベースラインを確立する
> - 変更は1つずつ行い、各変更の効果を RMSE で測定する
> - 「複雑にすれば良くなる」とは限らない

## ステップ1: ベースラインモデルの作成

### 何をしたか

2つの特徴量と RandomForestRegressor でシンプルなモデルを作成した。

```python
features = ["LotArea", "YearRemodAdd"]
model = RandomForestRegressor(n_estimators=100, random_state=1)
model.fit(X, y)
```

### なぜこの2特徴量か

「住宅価格と直感的に関係がある」列を選んだ。

| 特徴量 | 価格との関係 |
|---|---|
| `LotArea` | 敷地面積が広いほど価格が高い傾向 |
| `YearRemodAdd` | 最近リフォームされた住宅ほど価格が高い傾向 |

### ベースラインを作る重要性

> これ以降のすべての改善は「ベースラインと比べて RMSE が小さくなっているか」を基準に判断します。  
> ベースラインがないと、改善の効果を測定できません。

## ステップ2: 目的変数の対数変換

### 問題の発見：SalePrice の分布が歪んでいる

住宅価格のデータを見ると、一部の高額物件が極端に高く、**右に大きく歪んだ分布**になっている。

```
変換前: 価格の分布（右歪み）
  ████████████
  ██████████
  █████████
  ███████
  ████
  ██
  █                          ← 一部の超高額物件
  100k  200k  300k  400k  700k

変換後: log(価格)の分布（正規分布に近づく）
       ████████
     ██████████████
   ████████████████████
  ───────────────────────
  11.5  12.0  12.5  13.0
```

### なぜ歪みが問題なのか

RMSE は誤差を**二乗**するため、外れ値（超高額物件）の誤差が過大評価される。  
対数変換することで外れ値の影響が緩和され、モデルが全体的に学習しやすくなる。

### 実装

```python
# 学習時: SalePrice を対数変換してから学習
y = np.log1p(train_data["SalePrice"])   # log(1 + SalePrice)
model.fit(X, y)

# 予測時: 対数変換を元に戻す
predictions = np.expm1(model.predict(X_test))  # exp(予測値) - 1
```

### log1p / expm1 を使う理由

`log(0)` は計算できないため、`log(1 + x)` を使う `np.log1p` が安全。  
逆変換は `np.expm1`（`exp(x) - 1`）で元のスケールに戻す。

| 関数 | 計算式 | 用途 |
|---|---|---|
| `np.log1p(x)` | `log(1 + x)` | 学習前に目的変数を変換 |
| `np.expm1(x)` | `exp(x) - 1` | 予測後に元のスケールへ逆変換 |

## ステップ3: 特徴量エンジニアリング（既存列の加工）

### 考え方：「列を増やす」のではなく「列を変換・組み合わせる」

特徴量として使える列を `LotArea` と `YearRemodAdd` の2列に制限した状態でも、  
**既存の列を加工・組み合わせる**ことで情報を豊かにできる。

```
LotArea       → そのまま使う
              → 対数変換して外れ値を緩和（LotArea_log）

YearRemodAdd  → そのまま使う
              → 「経過年数」に変換（YearsSinceRemod）

LotArea × YearRemodAdd → 「広くて新しい」物件の相乗効果（Area_x_RemodYear）
```

### 追加した派生特徴量

| 特徴量 | 計算方法 | 直感的な意味 |
|---|---|---|
| `YearsSinceRemod` | `2007 - YearRemodAdd` | リフォームが古いほど価値が下がる |
| `LotArea_log` | `log(1 + LotArea)` | 面積の外れ値の影響を緩和 |
| `Area_x_RemodYear` | `LotArea × YearRemodAdd` | 広くて最近リフォームされた物件の相乗効果 |

### 基準年（2007年）の選び方

> データの売却年（`YrSold`）の中央値が 2007 年であるため、これを基準として「リフォームからの経過年数」を計算した。  
> 「いつからの経過年数か」を統一することで、モデルが一貫した基準で学習できる。

### 特徴量エンジニアリングの考え方

```
「このデータの背景にある現実」を考える

例1: LotArea は 1,000 〜 200,000 平方フィートと幅が広い
  → 広大な土地は「倍の面積でも倍の価値にはならない」
  → 対数変換で「面積増加の効果が逓減する」現実を反映できる

例2: YearRemodAdd は年号（1950, 2005 等）のままでは学習しにくい
  → 「何年前にリフォームしたか」の方が価格との関係が直感的
  → 経過年数に変換することでモデルが理解しやすくなる
```

## ステップ4: モデルの変更とアンサンブル

### より高性能なモデルへの切り替え

RandomForest だけでなく **XGBoost・LightGBM** と比較し、最も RMSE が低いモデルを選ぶ。

```python
candidates = {
    "RandomForest": RandomForestRegressor(...),
    "XGBoost":      XGBRegressor(...),
    "LightGBM":     LGBMRegressor(...),
}
for name, model in candidates.items():
    scores = cross_val_score(model, X, y, cv=5, scoring="neg_root_mean_squared_error")
    print(f"{name}: CV RMSE={-scores.mean():.4f}")
```

### VotingRegressor（回帰のアンサンブル）

分類タスクの `VotingClassifier` に対応する回帰版が `VotingRegressor`。  
各モデルの予測価格を**単純平均**して最終予測とする。

```
RandomForest → 予測価格 220,000 ─┐
XGBoost      → 予測価格 215,000 ─┼─ 平均 217,000 → 最終予測
LightGBM     → 予測価格 216,000 ─┘
```

**分類との違い**

| | VotingClassifier | VotingRegressor |
|---|---|---|
| 出力 | クラス確率（ソフト投票）または多数決（ハード投票） | 予測値の平均 |
| 使う場面 | 0/1 などのカテゴリ予測 | 価格などの連続値予測 |

## ステップ5: ハイパーパラメータの最適化

### 固定値の問題点

ステップ4までは `n_estimators=100` などの固定値を使っていた。  
最適な値はデータによって異なるため、自動的に探索する仕組みが必要。

### RandomizedSearchCV による探索

固定値リストではなく**確率分布**でパラメータ範囲を指定し、  
`n_iter=50` 回ランダムにサンプリングして最良の組み合わせを見つける。

```python
from scipy.stats import randint, uniform

param_dist = {
    "n_estimators":  randint(100, 600),    # 100〜599 の整数からランダムに選ぶ
    "learning_rate": uniform(0.01, 0.29),  # 0.01〜0.30 の実数からランダムに選ぶ
}
gs = RandomizedSearchCV(model, param_dist, n_iter=50, cv=5,
                        scoring="neg_root_mean_squared_error")
gs.fit(X, y)
print(gs.best_params_)   # 最良パラメータを確認
```

### チューニング後の VotingRegressor

各モデルを個別にチューニングし、チューニング済みのモデルで VotingRegressor を構成することで、  
「最良の状態のモデル3つ」によるアンサンブルを実現する。

```
① RF をチューニング   → tuned_rf
② XGB をチューニング  → tuned_xgb
③ LGBM をチューニング → tuned_lgbm

④ VotingRegressor([tuned_rf, tuned_xgb, tuned_lgbm])
    → 3つの最良モデルの平均 → 最終予測
```

## 精度改善プロセス全体の振り返り

### 時系列まとめ

```
ステップ1: LotArea・YearRemodAdd × RandomForestRegressor でベースライン作成
    ↓
ステップ2: SalePrice を対数変換（log1p）して学習・予測後に逆変換（expm1）
    ↓
ステップ3: 既存2列から派生特徴量を作成
           （YearsSinceRemod・LotArea_log・Area_x_RemodYear）
    ↓
ステップ4: XGBoost・LightGBM を追加比較し VotingRegressor でアンサンブル
    ↓
ステップ5: RandomizedSearchCV でハイパーパラメータを最適化
           チューニング済みモデルで VotingRegressor を再構成 → 最終モデル
```

### 各ステップの改善効果

| ステップ | 主な変更 | 精度改善の理由 |
|---|---|---|
| 1 | ベースライン作成 | 比較基準を確立 |
| 2 | 目的変数の対数変換 | 外れ値の影響を緩和し、モデルが学習しやすくなる |
| 3 | 派生特徴量の追加 | 既存情報を別の角度から表現し、パターンを発見しやすくする |
| 4 | モデル変更 + アンサンブル | 複数モデルの誤差を相互に補正する |
| 5 | ハイパーパラメータ最適化 | データに最適な設定値を自動探索する |

## 分類問題との比較（タイタニックとの違い）

| 観点 | タイタニック（分類） | 住宅価格（回帰） |
|---|---|---|
| 目的変数 | 生存（0/1） | 販売価格（連続値） |
| 主な評価指標 | Accuracy, CV accuracy | RMSE, CV RMSE |
| 目的変数の変換 | 不要 | 対数変換が有効（右歪みの場合） |
| 特徴量エンジニアリング | 新列の追加（Title等）が主 | 既存列の加工・変換も有効 |
| アンサンブル | VotingClassifier（ソフト投票） | VotingRegressor（平均） |
| 過学習の症状 | CVスコア高・Kaggleスコア低 | CV RMSEが低・Kaggleスコア高 |

## 機械学習改善の一般的な進め方（まとめ）

精度改善は以下のサイクルを繰り返すことで行う。

```
① ベースラインを作る（シンプルなモデル・少ない特徴量から始める）
    ↓
② 目的変数の分布を確認する
   → 歪んでいる場合は対数変換を検討
    ↓
③ 特徴量を改善する
   → 既存列の変換・組み合わせ → CV スコアで効果を測定
    ↓
④ モデルを改善する
   → 複数モデルを比較 → アンサンブルを検討
    ↓
⑤ ハイパーパラメータを最適化する
   → RandomizedSearchCV で自動探索
    ↓
⑥ Kaggle に提出して実際のスコアを確認
   → CV スコアと乖離が大きい場合はデータリーク・過学習を疑う
    ↓
⑦ ① に戻る
```

> **最も大切なこと**  
> 各ステップで「なぜこの手法を使うのか」「何の問題を解決しようとしているのか」を  
> 常に意識しながら改善を進めること。  
> 手法を目的にするのではなく、**「精度を上げるための手段」として使うことが重要**。
