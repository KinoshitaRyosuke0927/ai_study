# モデル・チューニング手法の概要

## 使用モデル

### 1. RandomForest（ランダムフォレスト）

#### 概要
複数の決定木を並列に学習させ、それぞれの予測結果を**多数決**で統合するアンサンブル手法。

#### 仕組み
1. 学習データからランダムにサンプルを復元抽出（**ブートストラップサンプリング**）
2. 各決定木は、特徴量のランダムなサブセットを使って学習
3. 全ての決定木の予測を多数決で統合して最終予測を出力

```
学習データ → [決定木1] ─┐
           → [決定木2] ─┼─ 多数決 → 最終予測
           → [決定木3] ─┘
```

#### 特徴
- 過学習に強い（各木がランダムに学習するため）
- 特徴量の重要度を出力できる
- ハイパーパラメータのチューニングがシンプル
- 大規模データでは学習・予測が遅くなる場合がある

#### 主なハイパーパラメータ（本コードで使用）
| パラメータ | 意味 |
|---|---|
| `n_estimators` | 決定木の本数（多いほど安定するが計算コスト増） |
| `max_depth` | 各決定木の最大深さ（深すぎると過学習） |
| `min_samples_split` | ノードを分割する最小サンプル数 |

---

### 2. XGBoost（エクストリーム勾配ブースティング）

#### 概要
決定木を**直列に**積み重ね、前の木の誤差を次の木が補正する**勾配ブースティング**の代表的な実装。

#### 仕組み
1. 最初の決定木で予測し、残差（誤差）を計算
2. 残差を学習する2本目の決定木を追加
3. これを繰り返し、モデルを逐次的に強化していく

```
学習データ → [木1] → 残差 → [木2] → 残差 → [木3] → ... → 合算 → 最終予測
```

#### 特徴
- 高い予測精度（Kaggleで長年トップ手法）
- 正則化項（L1/L2）が組み込まれており過学習しにくい
- 欠損値を内部で自動処理できる
- `learning_rate` が低いほど精度は上がるが学習が遅くなる

#### 主なハイパーパラメータ（本コードで使用）
| パラメータ | 意味 |
|---|---|
| `n_estimators` | 追加する決定木の本数 |
| `max_depth` | 各決定木の最大深さ |
| `learning_rate` | 各ステップの学習率（小さいほど慎重に学習） |

---

### 3. LightGBM（ライト勾配ブースティングマシン）

#### 概要
XGBoostと同じく勾配ブースティングの手法だが、Microsoft が開発した**高速・省メモリ**な実装。

#### 仕組み
XGBoost との主な違いは木の構築方向にある。

| | XGBoost | LightGBM |
|---|---|---|
| 木の成長方向 | 深さ優先（Level-wise） | 損失が最大の葉から展開（Leaf-wise） |
| 速度 | 普通 | 高速 |
| 精度 | 高い | XGBoost 以上になることが多い |
| 過学習リスク | 低め | `max_depth` 制限が重要 |

#### 特徴
- 大規模データでも高速に学習できる
- カテゴリ変数をそのまま扱える（本コードでは `get_dummies` 済みのため不使用）
- 少ないデータでは過学習しやすいため `max_depth` の調整が重要

#### 主なハイパーパラメータ（本コードで使用）
| パラメータ | 意味 |
|---|---|
| `n_estimators` | 追加する決定木の本数 |
| `max_depth` | 各決定木の最大深さ |
| `learning_rate` | 各ステップの学習率 |

## チューニング手法

### GridSearchCV（グリッドサーチ交差検証）

#### 概要
指定したハイパーパラメータの**全組み合わせ**を試し、最も性能が良い組み合わせを見つける手法。

#### 仕組み

```python
GridSearchCV(estimator, param_grid, cv=5, scoring="accuracy", n_jobs=-1)
```

1. `param_grid` に指定した全パラメータの組み合わせを列挙
2. 各組み合わせを `cv=5`（5分割交差検証）で評価
3. 平均スコアが最も高い組み合わせを `best_params_` として返す

#### 例（XGBoost の場合）
```
n_estimators: [100, 200]  × 2通り
max_depth:    [3, 4, 5]   × 3通り
learning_rate:[0.05, 0.1] × 2通り
─────────────────────────────────
合計: 2×3×2 = 12通り の組み合わせ
各組み合わせを 5-fold CV で評価 → 計 60 回学習
```

#### 特徴
- 確実に最良パラメータを見つけられる
- 組み合わせ数が多いと計算コストが増大する（`n_jobs=-1` で並列化して対策）

---

### RandomizedSearchCV（ランダムサーチ交差検証）

#### 概要
パラメータ空間から**ランダムにサンプリング**した組み合わせだけを評価する手法。GridSearchCV の「全探索」に対して「確率的探索」と呼ばれる。

#### 仕組み

```python
RandomizedSearchCV(estimator, param_dist, n_iter=50, cv=5, scoring="accuracy", n_jobs=-1, random_state=1)
```

1. `param_dist` に指定した**確率分布**から `n_iter` 回ランダムにパラメータをサンプリング
2. 各組み合わせを `cv=5` で評価
3. 平均スコアが最も高い組み合わせを `best_params_` として返す

#### GridSearchCV との比較

| | GridSearchCV | RandomizedSearchCV |
|---|---|---|
| 探索方法 | 全組み合わせを網羅 | ランダムに N 通りをサンプリング |
| パラメータ指定 | 固定値のリスト | 確率分布（`randint`・`uniform` 等） |
| 探索範囲 | 指定値のみ | 連続した広い範囲を指定できる |
| 計算コスト | 組み合わせ数に比例して増大 | `n_iter` で固定（制御しやすい） |
| 最良解の保証 | あり（列挙範囲内で） | なし（確率的） |

#### 本コードでの使い方
`randint(100, 500)` や `uniform(0.01, 0.29)` のように**連続した分布**でパラメータ範囲を指定し、`n_iter=50` で50通りをランダムに試している。GridSearch より少ない試行回数で広いパラメータ空間を効率よく探索できる。

```python
from scipy.stats import randint, uniform

param_dist = {
    "n_estimators": randint(100, 500),      # 100〜499 の整数からランダムサンプリング
    "learning_rate": uniform(0.01, 0.29),   # 0.01〜0.30 の実数からランダムサンプリング
}
inner_cv = RandomizedSearchCV(estimator, param_dist, n_iter=50, cv=5, ...)
```

### cross_val_score（交差検証スコア）

#### 概要
データを `k` 個に分割し、1つを検証用・残りを学習用として `k` 回学習・評価を繰り返す手法。

#### 仕組み（cv=5 の場合）

```
データ全体
┌────┬────┬────┬────┬────┐
│ 1  │ 2  │ 3  │ 4  │ 5  │
└────┴────┴────┴────┴────┘

1回目: [検証] [学習] [学習] [学習] [学習]
2回目: [学習] [検証] [学習] [学習] [学習]
3回目: [学習] [学習] [検証] [学習] [学習]
4回目: [学習] [学習] [学習] [検証] [学習]
5回目: [学習] [学習] [学習] [学習] [検証]
```

5回分の精度の**平均と標準偏差**を出力することで、モデルの安定性も評価できる。

#### 本コードでの使い方（Nested CV）
`RandomizedSearchCV` を一つの推定器として `cross_val_score` に渡すことで **Nested CV（二重交差検証）** を構成している。パラメータ選択と性能評価を異なるデータ分割で行うため、モデル選択バイアスを排除できる。

```python
inner_cv = RandomizedSearchCV(estimator, param_dist, n_iter=50, cv=5, ...)
outer_scores = cross_val_score(inner_cv, X, y, cv=5, scoring="accuracy")
# outer_scores が「パラメータ選択バイアスのない」汎化性能の推定値
```

### 特徴量重要度による選択（Feature Importance Selection）

#### 概要
モデルが予測に使った各特徴量の「寄与度（重要度）」を算出し、重要度が低い特徴量を除去する手法。ノイズとなる特徴量を取り除くことで過学習を抑え、精度・速度の向上が期待できる。

#### 仕組み（RandomForest の場合）
RandomForest の各決定木において、ある特徴量で分割したときに**不純度（ジニ係数）がどれだけ減少したか**を重要度として集計する。

```
重要度 = 全決定木における「その特徴量による不純度減少量の平均」
```

#### 注意点
- 閾値（平均値など）は固定ではなく、データによって調整が必要
- 重要度が低くても他の特徴量と組み合わせると効果がある場合もある
- **本コードでは後述のアプローチAに置き換え**。重要度の閾値を手動で決めるより、CV スコアを基準に逐次選択するほうが客観的かつ精度向上に直結するため

## 精度改善アプローチ

### アプローチA: 特徴量の逐次追加（Sequential Feature Addition）

#### 概要
ベースとなる少数の特徴量から出発し、候補を **1つずつ追加して CV スコアが改善した場合のみ採用**する手法。「全部載せ」による過学習を防ぎ、本当に貢献する特徴量だけを残す。

#### 仕組み

```
ベース: ["Pclass", "Sex", "SibSp", "Parch"]  CV=0.8081

+ Title    → CV=0.8204  ✓ 採用  （スコア改善 → selected に追加）
+ Fare     → CV=0.8260  ✓ 採用
+ Embarked → CV=0.8237  ✗ 却下  （スコア改善なし → 除外）
...
```

スコアが上がった特徴量のみ `selected_features` に追加していき、最終的に採用リストを確定する。

#### 特徴量重要度による選択との違い

| | 特徴量重要度による選択 | 特徴量の逐次追加（アプローチA） |
|---|---|---|
| 選択基準 | 重要度スコアの閾値（手動設定） | CV accuracy の改善有無（自動判断） |
| 評価方法 | 全特徴量を一括で学習・評価 | 1つずつ追加しながら評価 |
| 閾値の恣意性 | あり（閾値を変えると結果が変わる） | なし（CV スコアが基準） |
| 計算コスト | 低い | やや高い（特徴量数 × CV 回数） |

#### 本コードでの実装

```python
base_features = ["Pclass", "Sex", "SibSp", "Parch"]
candidates_to_add = ["Title", "Fare", "Embarked", "HasCabin", "FamilySize", "IsAlone"]

for feat in candidates_to_add:
    score = cv_score(selected_features + [feat])
    if score > base_score:
        selected_features.append(feat)
        base_score = score
```

### アプローチB: 前処理リークの排除（Preventing Data Leakage）

#### 概要
**データリーク**とは、テストデータの情報が意図せず学習・前処理に混入してしまうこと。リークがあると CV スコアは高く出るが、実際のテストデータに対する精度は低くなる。

#### 修正前の問題点
Title の Rare 判定を **train と test を結合したデータ**で行っていた。

```python
# 修正前: test の Title 分布が Rare 判定に混入（リーク）
combined = pd.concat([train_data, test_data])
rare_titles = combined["Title"].value_counts()[...].index
```

test に稀な敬称があった場合、それが `Rare` に分類されるかどうかに test データの情報が使われてしまう。

#### 修正後
**train だけで** Rare 判定し、同じ基準を test にも適用する。

```python
# 修正後: train のみで Rare を決定し、test に同じ基準を適用
rare_titles = train_data["Title"].value_counts()[...].index
train_data["Title"] = train_data["Title"].replace(rare_titles, "Rare")
test_data["Title"]  = test_data["Title"].replace(rare_titles, "Rare")  # 同じ基準を適用
```

同様に、Age の中央値・Fare の中央値・Embarked の最頻値もすべて **train のみ**で計算し、test に適用している。

### アプローチC: Age の欠損補完影響の検証

#### 概要
`Age` 列は約 20% が欠損しており、補完した値は「推定値」に過ぎない。補完値がモデルにノイズを与えて精度を下げていないかを、**Age あり/なしを明示的に比較**することで検証する。

#### なぜ Age を逐次追加の候補に含めないのか
アプローチA の逐次追加に Age を含めると、他の特徴量が追加された後の状態で評価されるため、「Age 単独の影響」が他の特徴量との組み合わせ効果に埋もれてしまう。アプローチC では、アプローチA で確定した特徴量セットを固定した上で Age だけを独立して比較することで、**補完ノイズの影響を純粋に判断**できる。

#### 仕組み

```python
# アプローチA で確定した特徴量セットに対して Age あり/なしを比較
score_without_age = cv_score(selected_features)           # Age なし
score_with_age    = cv_score(selected_features + ["Age"]) # Age あり

if score_with_age > score_without_age:
    selected_features.append("Age")  # 改善 → 採用
else:
    pass                              # 改善なし → 補完がノイズの可能性
```

#### 判断基準
| 結果 | 解釈 |
|---|---|
| Age あり > Age なし | 欠損補完の精度が十分 → 採用 |
| Age あり ≤ Age なし | 補完値がノイズになっている → 除外 |

## まとめ

| | RandomForest | XGBoost | LightGBM |
|---|---|---|---|
| 学習方式 | 並列（バギング） | 直列（ブースティング） | 直列（ブースティング） |
| 速度 | 普通 | 普通 | 高速 |
| 精度 | 高い | より高い | より高い |
| 過学習耐性 | 強い | 強い | `max_depth` 調整が必要 |
| 特徴 | シンプルで安定 | 高精度・正則化あり | 大規模データに強い |
