## ステップ1: データの理解（EDA）

### データ構造の把握

| 項目 | 内容 |
|---|---|
| 学習データ | 42,000枚（label + pixel0〜pixel783 = 785列） |
| テストデータ | 28,000枚（pixel0〜pixel783 = 784列、label なし） |
| 画像サイズ | 28×28ピクセル = 784個の数値 |
| ピクセル値 | 0（白）〜 255（黒）の整数 |

```
各行が1枚の画像を表す:
pixel0  pixel1  pixel2  ... pixel27       ← 1行目
pixel28 pixel29 pixel30 ... pixel55       ← 2行目
  ...                       ...
pixel756 ...              pixel783        ← 28行目
```

### EDA で判明した重要な事実

```
1. クラス分布はほぼ均等（3,795〜4,684枚）→ クラス不均衡の対策不要
2. ピクセル値の 80.8% がゼロ（白背景）→ スパースなデータ
3. 非ゼロピクセルの平均値: 174.4（白か黒かのどちらかに偏る分布）
4. 欠損値なし → 補完処理不要
5. 4 vs 9、3 vs 8 など混同しやすいペアが存在する
```

## ステップ2: ベースラインモデル（digit_recognizer.py）

### 何をするか

まず LightGBM（機械学習モデル）で「784個の数値を特徴量としてそのまま使う」シンプルなモデルを作る。

### EDA の発見をコードに反映した前処理

```python
X = train.drop("label", axis=1).values / 255.0  # 0〜1 に正規化
y = train["label"].values
```

**なぜ 255 で割るのか**:  
LightGBM はピクセル値の大小でツリーを分岐させる。  
0〜255 のままでも動くが、0〜1 に揃えることで学習が安定し、  
後に CNN へ移行したときも同じ前処理が使える。

### StratifiedKFold を使う理由

```python
skf = StratifiedKFold(n_splits=5, shuffle=True, random_state=1)
```

| CV の種類 | 使う場面 | 理由 |
|---|---|---|
| TimeSeriesSplit | 時系列データ（store_sales など） | 未来のデータで過去を学習しないため |
| **StratifiedKFold** | **画像分類など多クラス問題** | **各 fold のクラス比率を揃えて公平に評価するため** |

画像データは時系列ではないので TimeSeriesSplit は不適切。  
StratifiedKFold を使うと、各 fold に 0〜9 が均等に含まれる。

### ベースラインの結果

```
CV Accuracy: 0.9753
```

## ステップ3: CNN モデルへの移行（digit_recognizer_cnn.py）

### なぜ LightGBM では限界があるのか

LightGBM（および RandomForest・XGBoost などの機械学習モデル）は  
「784個の数値を**独立した特徴量**」として扱う。

```
LightGBM が見るもの:
  pixel350 = 200, pixel351 = 0, pixel378 = 210, ...（バラバラな数値の羅列）

人間が見るもの:
  ┌─────────────────┐
  │      ■■■        │  ← 「縦線がある」
  │       ■         │  ← 「曲線がある」
  │      ■■         │  ← 「これは 7 だ」
  └─────────────────┘
```

**LightGBM の限界**: 隣り合うピクセルが「縦線・横線・曲線」を形成しているという  
「空間的なつながり」を学習できない。pixel350 と pixel351 が隣接していることを知らない。

## CNN（畳み込みニューラルネットワーク）とは

### 基本的な考え方

CNN は人間の視覚野を模倣した構造で、**画像の「局所的なパターン」を段階的に学習する**。

```
ステップ1（浅い層）: 単純なパターンを検出
  ┌─┐   ┌─┐   ┌─┐
  │■│   │■│   │ │   ← 縦線・横線・斜線などのエッジ
  │■│   │ │   │■│
  └─┘   └─┘   └─┘

ステップ2（中間層）: 複雑なパターンを検出
  組み合わせ → 曲線・角・交差点など

ステップ3（深い層）: 数字全体の形を識別
  組み合わせ → 「0のループ」「1の縦棒」「7の屈折」など
```

### CNN の3つの主要な処理

#### 1. 畳み込み層（Conv2D）

小さな「フィルター（カーネル）」をスライドさせて、画像内のパターンを探す。

```
入力画像（28×28）
  ┌────────────────┐
  │ 0  0  0 255  0 │
  │ 0 255 255 255 0 │   3×3 のフィルターをスライド
  │ 0  0  0 255  0 │   ─────────────────────────→ 特徴マップを生成
  └────────────────┘

filters=32 → 32種類のフィルターを同時に学習
             （縦線用・横線用・斜線用...など）
```

```python
x = layers.Conv2D(32, 3, padding="same", activation="relu")(x)
# 32: フィルター数（32種類のパターンを学習）
# 3 : カーネルサイズ（3×3 ピクセルの窓）
# padding="same": 出力サイズを入力と同じに保つ
```

#### 2. プーリング層（MaxPooling2D）

特徴マップを縮小し、位置の微小なズレに頑健にする。

```
4×4 の特徴マップ
  ┌───────────┐
  │ 2  8  4  1 │
  │ 3  7  5  2 │   → 2×2 領域の最大値を取る → ┌───┐
  │ 6  1  3  8 │                               │ 8  5 │
  │ 2  4  7  5 │                               │ 6  8 │
  └───────────┘                               └───┘
```

```python
x = layers.MaxPooling2D(2)(x)
# 2×2の窓で最大値をとり、特徴マップを半分のサイズに圧縮
# → 数字が少し傾いていても認識できるようになる
```

#### 3. Dropout（過学習防止）

学習中にランダムにニューロンを無効化し、特定のパターンへの依存を防ぐ。

```python
x = layers.Dropout(0.25)(x)
# 学習時: 25% のニューロンをランダムに無効化 → 汎化性能向上
# 推論時: 全ニューロンを使用（自動的に切り替わる）
```

### CNN のアーキテクチャ（全体構造）

```
入力 (28×28×1)
    ↓
【畳み込みブロック1】
  Conv2D(32フィルター, 3×3) → BatchNorm → ReLU
  Conv2D(32フィルター, 3×3) → BatchNorm → ReLU
  MaxPooling(2×2) → 特徴マップが (14×14) に縮小
  Dropout(25%)
    ↓  ← 「縦線・横線・斜線」などの単純パターンを学習
【畳み込みブロック2】
  Conv2D(64フィルター, 3×3) → BatchNorm → ReLU
  Conv2D(64フィルター, 3×3) → BatchNorm → ReLU
  MaxPooling(2×2) → 特徴マップが ( 7× 7) に縮小
  Dropout(25%)
    ↓  ← 「曲線・交差」などの複雑なパターンを学習
【畳み込みブロック3】
  Conv2D(128フィルター, 3×3) → BatchNorm → ReLU
  Dropout(25%)
    ↓  ← 「数字の部分的な形状」を学習
【全結合層】
  Flatten（2次元 → 1次元ベクトルに変換）
  Dense(256) → BatchNorm → Dropout(50%)
    ↓
【出力層】
  Dense(10, softmax) → 10クラスの確率 [0.01, 0.02, 0.95, ...]
```

### BatchNormalization（バッチ正規化）とは

各層の出力を正規化（平均0・分散1）することで学習を安定させる技術。

```python
x = layers.BatchNormalization()(x)
# 効果1: 学習率を大きくできるため学習が速くなる
# 効果2: 過学習を抑制する正則化効果がある
```

## データ拡張（Data Augmentation）

### なぜ必要か

実際の手書き文字は、書く人によって傾きや大きさが異なる。  
学習データをランダムに変形して「水増し」することで、  
モデルが様々なパターンに対応できるようになる。

```
元の画像         回転           シフト          ズーム
┌──────┐     ┌──────┐     ┌──────┐     ┌──────┐
│  ■   │     │  ■/  │     │    ■ │     │  ■   │
│  ■   │  →  │  /   │  →  │    ■ │  →  │ ■■   │
│  ■   │     │ /    │     │    ■ │     │  ■   │
└──────┘     └──────┘     └──────┘     └──────┘
```

```python
data_augmentation = keras.Sequential([
    layers.RandomRotation(0.08),        # ±8% 回転（約±29度）
    layers.RandomTranslation(0.1, 0.1), # 上下左右に ±10% シフト
    layers.RandomZoom(0.1),             # ±10% ズーム
])
```

> **注意**: 数字は上下反転すると別の数字になるため `RandomFlip` は使わない。  
> （6 を上下反転すると 9 に見える、など）

### 学習時のみ拡張を適用する仕組み

```python
# 入力の直後に data_augmentation を挟む
inputs = keras.Input(shape=(28, 28, 1))
x = data_augmentation(inputs)   # 学習時のみ変形、推論時はスキップ
```

Keras の `data_augmentation` レイヤーは、`model.fit()` 中は変形を適用し、  
`model.predict()` 中は自動的にスキップする。

## 学習のコントロール（Callbacks）

### EarlyStopping

検証 Accuracy が改善しなくなったら、自動的に学習を終了する。

```python
EarlyStopping(
    monitor="val_accuracy",   # 監視する指標
    patience=10,              # 10 epoch 改善なしで停止
    restore_best_weights=True # 最良の重みを復元してから終了
)
```

```
epoch  10: val_accuracy=0.9920  ← 改善中
epoch  11: val_accuracy=0.9925  ← 改善中
epoch  12: val_accuracy=0.9923  ← 改善なし（1回目）
...
epoch  21: val_accuracy=0.9921  ← 改善なし（10回目）→ 停止 & epoch11の重みを復元
```

**なぜ重要か**: `epochs=50` と設定しても、過学習が始まった時点で自動停止するため、  
最良の状態のモデルを得られる。

### ReduceLROnPlateau

検証 loss が改善しなくなったら、学習率を自動で下げる。

```python
ReduceLROnPlateau(
    monitor="val_loss",
    factor=0.5,       # 学習率を半分に（0.001 → 0.0005）
    patience=4,       # 4 epoch 改善なしで学習率を下げる
    min_lr=1e-6       # 学習率の下限
)
```

```
学習率 0.001 → 4 epoch 改善なし → 0.0005 → さらに4 epoch 改善なし → 0.00025
```

**なぜ重要か**: 学習の終盤に細かく調整することで、より精度が高い状態で収束できる。

## 入力データの形状変換

LightGBM と CNN では、入力データの形状が異なる。

```python
# LightGBM: 784個の数値を「独立した特徴量の列」として扱う
X = train.drop("label", axis=1).values / 255.0
# shape: (42000, 784) ← 行=サンプル数, 列=特徴量数

# CNN: 28×28の「画像」として扱う（チャンネル数=1: グレースケール）
X = train.drop("label", axis=1).values.reshape(-1, 28, 28, 1) / 255.0
# shape: (42000, 28, 28, 1) ← サンプル数, 高さ, 幅, チャンネル数
```

> **チャンネルとは**  
> グレースケール画像はチャンネル数=1（輝度のみ）  
> カラー画像はチャンネル数=3（R・G・B）  
> CNN はこの「チャンネル」の次元を含む 4 次元テンソルを入力とする

## LightGBM vs CNN の比較

| 比較項目 | LightGBM（ベースライン） | CNN |
|---|---|---|
| データの扱い | 784個の独立した数値 | 28×28 の画像 |
| 空間情報 | **考慮しない** | **考慮する**（隣接関係を学習） |
| パターン認識 | ピクセル値の大小でツリーを分岐 | フィルターで局所パターンを検出 |
| 前処理 | reshape 不要 | (N, 28, 28, 1) に reshape 必須 |
| 過学習対策 | 正則化パラメータ | Dropout + BatchNorm + データ拡張 |
| 学習時間 | 速い | 遅い（GPU 推奨） |
| CV 方法 | StratifiedKFold | train_test_split（検証データで監視） |
| **Accuracy** | **0.9753** | **0.9951** |

## 精度改善プロセス全体の振り返り

### 時系列まとめ

```
ステップ1: EDA
  → クラスは均等・ピクセルの80.8%がゼロ・欠損値なし
    ↓
ステップ2: ベースラインモデル（LightGBM）
  → 784ピクセルを独立した特徴量として使用
  → CV Accuracy = 0.9753
    ↓
ステップ3: CNNモデルへの移行
  → 28×28の画像として空間的パターンを学習
  → データ拡張で汎化性能を向上
  → Callback で学習を自動コントロール
  → Val Accuracy = 0.9951
```

### 各ステップで使った手法と目的

| ステップ | 主な手法 | 目的 |
|---|---|---|
| EDA | クラス分布・ピクセル値分布・平均画像・混同ペア | データの性質を把握して設計方針を決める |
| ベースライン | LightGBM + StratifiedKFold | 比較基準を確立する |
| CNN | Conv2D + BatchNorm + MaxPool + Dropout | 画像の空間的パターンを段階的に学習する |
| データ拡張 | RandomRotation / Translation / Zoom | 学習データを水増しして汎化性能を上げる |
| EarlyStopping | val_accuracy を監視 | 過学習前に自動停止して最良の重みを保持 |
| ReduceLROnPlateau | val_loss を監視 | 学習終盤に学習率を下げて細かく収束させる |

## CNNを使う問題とそうでない問題の判断基準

| 問題の種類 | 推奨するアプローチ |
|---|---|
| **画像データ**（ピクセル値の配列） | **CNN** |
| テキストデータ（文章・単語） | RNN / Transformer |
| テーブルデータ（数値・カテゴリの表形式） | LightGBM / XGBoost |
| 時系列データ（日付・時刻つき） | LightGBM + TimeSeriesSplit / LSTM |

> **判断のポイント**  
> 「データに空間的・時間的な構造があるか？」  
> 画像は「隣接ピクセルのパターン」が意味を持つ → CNN が有効  
> テーブルは「各列が独立した特徴量」 → 勾配ブースティングが有効

## 機械学習改善の一般的な進め方（まとめ）

精度改善は以下のサイクルを繰り返すことで行う。

```
①  問題の性質を理解する（EDA）
    → 画像なのか・表なのか・時系列なのか
    → クラスは均等か・欠損値はあるか
    ↓
②  問題に合ったモデルを選ぶ
    → 画像 → CNN、表形式 → LightGBM
    ↓
③  シンプルなベースラインを作って精度を確認する
    ↓
④  改善を加えて精度を測定する
    → CV スコアまたは検証データで確認
    ↓
⑤  Kaggle に提出して実際のスコアを確認する
    → CV スコアと大きく乖離する場合は過学習を疑う
    ↓
⑥  ①に戻る
```

> **最も大切なこと**  
> 「なぜその手法を使うのか」を常に意識すること。  
> CNN を使うのは「画像の空間的パターンを学習できるから」であり、  
> ツールを使うことが目的ではなく、**「精度を上げるための手段」として使うことが重要**。
