# 補足資料

## 1. サービス概要

### Azure Speech to Text（Azure AI Speech）

Microsoft が提供する音声 AI スイートの一部。音声テキスト変換（STT）だけでなく、テキスト読み上げ（TTS）・音声翻訳・発音評価・LLM 音声統合など複数の機能をまとめて利用できる。Microsoft エコシステム（Azure・Teams・Office 365）との連携実績が豊富。

### Google Cloud Speech-to-Text

Google が提供する音声テキスト変換専用の API。新世代モデル **Chirp 3** を採用し、125 言語以上に対応。単一機能（STT のみ）に特化したシンプルな設計で、セットアップのしやすさが特徴。

---

## 2. 機能比較

| 機能 | Azure Speech | Google Cloud STT |
|---|---|---|
| リアルタイム認識 | あり | あり（gRPC ストリーミング） |
| バッチ処理 | あり | あり（最大 480 分） |
| 話者識別（Diarization） | あり（最大 35 人） | あり |
| カスタムモデル | あり（音響・言語・発音データで学習可） | あり（限定的） |
| テキスト読み上げ（TTS） | あり（ニューラル音声・カスタム音声） | なし |
| 音声翻訳 | あり（リアルタイム・バッチ） | なし（別サービス） |
| 発音評価 | あり（言語学習向け） | なし |
| 自動句読点 | あり | あり |
| 言語検出 | あり | あり |
| 日本語対応 | あり | あり（方言含む） |
| 対応言語数 | 140 以上 | 125 以上 |

## 4. API・SDK の使いやすさ

### Azure Speech

- **SDK 対応言語**: Python・C#・JavaScript・Java・C++ など多数
- **Speech Studio**: コード不要の UI ベースでモデル設定・テストが可能
- **ドキュメント**: Microsoft Learn に日本語ドキュメントが充実
- **統合**: Azure リソースとして一元管理でき、他の Azure サービスとの連携が容易

### Google Cloud Speech-to-Text

- **SDK 対応言語**: Python・Java・Node.js・C#・Go など
- **API 形式**: REST / gRPC（シンプルで直感的）
- **ドキュメント**: 英語メインで日本語資料は限定的
- **統合**: Google Cloud エコシステムとの連携が強い

## 5. OpenAI Whisper（ローカル実行）との比較

### Whisper（ローカル）の特性

- tiny / small / medium / large の 4 段階でモデルサイズを選択可能
- 50 言語以上に対応、日本語精度が高い
- ローカル実行のため無料・オフライン動作可能・データがクラウドに送信されない
- CPU 実行の場合、長時間音声の処理に時間がかかる（30 分音声で数分程度）

### 各サービスの優位点・劣位点

| | Azure Speech | Google Cloud STT |
|---|---|---|
| **Whisper に対する優位点** | 話者識別・発音評価・TTS など Whisper にない機能がある。カスタムモデルで業界用語に対応可能 | セットアップがシンプル。新世代モデルの継続的改善 |
| **Whisper に対する劣位点** | 料金は Whisper API の約 3 倍。クラウド依存でオフライン不可 | 料金は Whisper API の約 4 倍。STT 以外の機能がない。独立評価での精度は Whisper 以下の傾向 |

## 6. サービス選択ガイド

| 要件 | 推奨 | 理由 |
|---|---|---|
| コスト最優先・高精度 | Whisper ローカル / API | 精度とコストのバランスが最良 |
| オフライン・データをクラウドに送りたくない | Whisper ローカル | ローカル実行対応はこれのみ |
| 話者識別が必要 | Azure Speech | 最大 35 人まで対応 |
| 業界固有の用語を学習させたい | Azure Speech | Custom Speech でカスタムモデル構築可能 |
| TTS・翻訳もまとめて使いたい | Azure Speech | 統合スイートとして利用できる |
| セットアップを手早く済ませたい | Google Cloud STT | API がシンプルで導入コストが低い |
| Microsoft エコシステムに統合したい | Azure Speech | Teams・Office との連携実績あり |

---

## 7. まとめ

本プロジェクト（発表練習アプリ）では、**Whisper（small モデル・ローカル実行）** を採用した。  
採用理由：無料・オフライン動作・日本語精度が高い・モデルサイズを状況に応じて切り替えられる。

Azure Speech / Google Cloud STT は、以下のような要件が加わった場合の移行先候補となる。

- 話者識別（誰がどの部分を発言したか）を活用したい
- カスタムモデルで特定ドメイン（医療・法律・技術用語）の精度を向上させたい
- 長時間音声（30 分以上）のバッチ処理を高速化したい
- エンタープライズ環境で SLA・コンプライアンスが必要
