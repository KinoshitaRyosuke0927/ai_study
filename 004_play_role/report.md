## STEP2 技術調査

### 技術概要

ブラウザで録音した音声・または動画ファイルを受け取り、Whisperで日本語テキストに変換する。
変換したテキストをAzure OpenAI（GPT）に送信し、指定した役割のキャラクターとして振る舞ったフィードバックを生成させる技術。

フィードバックは毎回JSON形式で出力させ、良かった点・改善点・質問・次のアクションを構造化して取得する。
さらにフィードバック履歴をCSVに蓄積し、各レビュアーの傾向をプロファイルとして管理することで、継続的に精度の高い（一貫性のある）フィードバックを返せるようにする。

### どのような課題を解決できるか

| 課題 | 解決内容 |
|---|---|
| 発表練習の相手がいない | AIが複数の立場で即座にフィードバックを返す |
| 毎回同じ観点のフィードバックになりがち | 教授・上司・同僚・初学者など異なる視点を役割として切り替えられる |
| フィードバックが主観的で再現性がない | JSON形式で構造化出力し、良かった点・改善点を一定フォーマットで取得する |
| 改善しているかどうか分からない | 過去のフィードバック履歴を蓄積し、改善・繰り返し指摘を自動分析してプロンプトに反映する |
| 音声をテキストに起こす手間がかかる | Whisperで自動文字起こし + Azure OpenAIで校正まで自動化する |

### 代表的なAPI・ツール・ライブラリ

| 名称 | 概要 | 特徴 |
|---|---|---|
| OpenAI Whisper | 音声認識モデル | ローカル実行可能・日本語対応・複数モデルサイズ（tiny〜large） |
| Azure OpenAI（GPT） | テキスト生成AI | 高精度・日本語品質が高い・JSON出力モード対応 |
| FastAPI | Python製Webフレームワーク | 非同期処理対応・自動ドキュメント生成・型安全 |
| ffmpeg | 動画・音声処理 | 動画から音声抽出・フォーマット変換に使用 |
| OpenCV | 動画解析 | スライド切替検出（フレーム差分分析）に使用 |

### 調査して感じた疑問点・気になる点

- Whisperの認識精度はモデルサイズによってどの程度変わるか（small vs medium vs large）
- 長い発表（30分以上）の場合、文字起こし時間はどの程度かかるか
- Azure OpenAIのJSONモードは必ず正しいJSONを返すか（パースエラー対策は必要か）
- 役割プロンプトの品質によってフィードバックの有用性がどう変わるか
- CSVによる履歴管理は件数が増えると読み込みが遅くなる可能性があるか

## STEP3 作成するもの決定

### 作成するプロトタイプ案

1. ブラウザで録音した音声を文字起こしし、AIが複数役割でフィードバックするWebアプリ
2. 音声ファイルをアップロードすると文字起こし結果と要約を返すCLIツール
3. 発表動画をアップロードするとスライドごとに分析するバッチ処理

### 選んだプロトタイプ

1. ブラウザで録音した音声を文字起こしし、AIが複数役割でフィードバックするWebアプリ

### 作成計画

**目的（何を確かめたいか）**

Whisper + Azure OpenAI を組み合わせることで、
音声入力 → 文字起こし → AI役割別フィードバック → 履歴蓄積 という一連の流れが
Webアプリとして実現可能かを検証する。

**成功基準の定義**

- ブラウザで録音した音声がWhisperで日本語テキストに変換される
- 指定した役割（教授・上司・同僚など）のAIがJSON形式でフィードバックを返す
- フィードバック履歴がCSVに保存され、2回目以降のコメントに過去傾向が反映される
- 動画をアップロードするとスライド切替を検出し、スライドごとの発言を紐づけられる

## STEP4 開発環境決定

### 使用するライブラリやAPI、モデルの比較

| 項目 | OpenAI Whisper (local) | Azure Speech to Text | Google Cloud STT |
|---|---|---|---|
| 実行場所 | ローカル | クラウド | クラウド |
| 日本語精度 | ◎ 高品質 | ○ 十分 | ○ 十分 |
| コスト | 無料（GPU不要） | 従量課金 | 従量課金 |
| オフライン利用 | ◎ 可能 | ✕ 不可 | ✕ 不可 |
| モデルサイズの選択 | ◎ tiny〜large | ✕ 不可 | ✕ 不可 |

| 項目 | Azure OpenAI (GPT) | OpenAI API (GPT) | Google Gemini API |
|---|---|---|---|
| 日本語対応 | ◎ 非常に高品質 | ◎ 非常に高品質 | ○ 十分な品質 |
| JSONモード | ◎ 対応 | ◎ 対応 | △ 限定的 |
| 社内利用 | ◎ Azureなので安心 | △ ポリシー確認要 | △ ポリシー確認要 |
| ドキュメント | ◎ 充実 | ◎ 充実 | ○ 充実 |

### 選んだ環境

- **音声認識**: OpenAI Whisper（`small`モデル、ローカル実行）
  - 無料・オフライン動作可能・日本語精度が高い
- **テキスト生成AI**: Azure OpenAI（GPT）
  - 社内環境でのセキュリティ要件を満たす・JSON出力モード対応
- **Webフレームワーク**: FastAPI + Jinja2 + JavaScript
  - Pythonで統一・非同期処理対応・実装コストが低い
- **データ永続化**: CSVファイル（DBは使用しない）
  - PoC段階での実装コスト最小化・ファイル単体で確認しやすい

## STEP6 学習内容まとめ

### できたこと

- Whisper（smallモデル）を使ってブラウザ録音音声を日本語テキストに変換できた
- Azure OpenAI でWhisperの文字起こし結果を自然な文章に自動校正できた
- 12種類の役割（教授・上司・同僚・初学者・開発者・PM・PO・友人・VTuber4名）を定義し、それぞれの立場で構造化フィードバックを出力できた
- フィードバックをJSON形式（summary / good_points / improvement_points / role_specific_concern / questions / next_actions）で統一的に取得できた
- レビュアーをCSVで管理し、追加・削除・名前変更のCRUD操作をAPIで実装できた
- フィードバック履歴をCSVに蓄積し、直近5件からルールベースでプロファイルを自動生成できた
- 表現ゆれ正規化辞書（「結論が遅い」「最初に結論がない」→「結論提示が遅い」など）を実装できた
- 過去プロファイルを次回コメント生成のプロンプトに自動注入し、継続的なフィードバックを実現できた
- 動画ファイル（mp4/webm/mov）をアップロードしてffmpegで音声抽出し、Whisperで文字起こしできた
- OpenCVでフレーム差分を分析してスライド切替タイミングを検出し、スライドごとの発言テキストを紐づけられた
- Whisperのモデルを遅延ロード（初回リクエスト時にロード）することで、サーバー起動時間を短縮できた

### できなかったこと

| 項目 | 理由 |
|---|---|
| 長い発表（30分以上）への対応 | Whisperのローカル実行はCPU処理のため、長時間音声の文字起こしに数分かかる場合があった |
| フィードバックの品質を定量的に評価すること | 「良いフィードバック」の基準設計まで手が回らなかった |
| CSVの同時書き込み耐性 | PoC優先のため、複数リクエストの同時書き込みは非対応 |
| データ件数増加時のパフォーマンス最適化 | CSVの全件読み込みのため、データ増加に伴って遅くなることが想定される |
| フロントエンドのUI改善 | 最小構成で実装したため、デザインや操作性に改善余地がある |

### 気づいたこと・学んだこと

- プロンプト（役割定義）の品質がフィードバックの有用性に直結する。役割の「話し方」「観点の優先度」を具体的に指示するほど一貫性が上がった
- JSON出力モード（`response_format={"type": "json_object"}`）を指定することで、パースエラーをほぼ排除できた
- Whisperのモデルサイズ（tiny / small / medium / large）によって精度と処理速度のトレードオフがある。実務では`medium`以上が望ましい
- 表現ゆれ（「結論が遅い」と「最初に結論がない」）が正規化されていないと、プロファイルの集計精度が落ちることを実感した
- ffmpegの存在チェックとエラーハンドリングは事前に組み込まないと、環境依存の問題が起きやすいことが分かった
- CSVは簡単に始められるが、件数が増えると全件読み込み + フィルタの処理が重くなるため、本格運用ではDBへの移行が必要

### 次回やってみたいこと・改善したいこと

- Whisperの処理を非同期（バックグラウンドタスク）で実行し、長時間音声でもUI側がブロックされないようにしたい
- CSVをSQLiteまたはPostgreSQLに移行し、同時書き込み耐性とクエリ効率を改善したい
- フィードバックの品質評価指標（例：ユーザーが「役立った」と評価した割合）を設計・実装したい
- プロンプトのA/Bテストを実施し、役割定義の改善を定量的に進めたい
- 音声入力だけでなく、テキスト直接入力にも対応し、コードレビュー練習などにも使えるようにしたい
